# Computer V0：账号授权、执行版本与试点准备

2026-10-27，北京时间。接续 [Worker 桥接](assistant-computer-worker-20261027.md)。本轮接通生产装配中的可选路由，并完成 79 隔离数据库的真实授权链路验收；本人账号的真实模型与多端验收另行记录，不能由确定性运行时试验替代。

## 授权与路由

`ComputerRuntime` 由部署配置显式列出租户及本人账号。只有数据库中该用户个人助理线程及其保留的历史 Session 才会选择电脑；普通任务保留原后端。用户输入里的 thread 名称、工具参数或开关不构成电脑访问权。停用账号、成员关系撤销和已经失效的个人会话会拒绝，不能靠换成临时后端规避这项检查。

Worker 需要固定镜像 digest、内部节点地址及私钥，并采用 `worker_cli_deferred`；API 与接收器只需同一账号范围来维护执行版本，不需要节点私钥。已有发布配置固定了其他执行后端时拒绝覆盖；不支持的 remote CLI、非 SDK 运行时及无法实施的限制性出站策略明确拒绝。Docker 边界记为 delegated，未冒充 full enforcement。

`CanonicalComputerAccess` 在节点端独立检查当前账号、租户成员关系、Session 与个人线程、真实 Run、当前 SandboxLease 和 ComputerLease。命令首次校验后，经过 Docker / 参数传输还会再检查一次。启动与生命周期也经过授权；只允许已验证持有者的停止或清理操作在业务权限撤销后继续进行。

节点默认 canonical 模式；跳过业务身份的 probe 模式只允许数据库名恰为 `harness_computer_probe`，不能用于生产库。API 在鉴权之前不解析命令体，失败不回显私有参数。

## 执行版本

0051 增加 nullable `run_fencing_token` 和相应约束。该迁移此前未上线，本轮继续完善；原用户、消息及绑定表不改结构。

首次使用电脑时读取当前真实 Run 版本。启用电脑的 `PostgresRunRepository` 在正常状态 CAS 的同一数据库事务中推进电脑授权版本；失败的 CAS 不改变电脑权限。审批暂停及恢复可以沿用当前执行权，暂停时不允许发新命令。Worker 以同一状态重新领取任务时，故意不推进旧电脑授权；旧持有者的后续命令和续期因此被拒绝。

版本拒绝不声称能够撤回已经执行的外部动作。已接受进程仍由监督器、租约到期及清理契约管理；新执行者须先完成物理恢复，不能与旧执行者同时写盘。

默认关闭的部署不会查询新电脑表，兼容迁移前的原任务路径。API、Worker、飞书和微信进程启用范围必须一致，避免审批由旧版本进程更新时丢失授权版本衔接。

## 清理归属

修复回收器按后端划分租约：OpenSandbox 的库存不能把 `docker-computer` 的活动或过期租约标为缺失；同时修复延迟句柄与平台 ID 不同时误关租约的问题。平台 Run 标签按租户匹配，缺少租户的旧标签保守留待确认。

79 当前 OpenSandbox 库存按专属 sandbox ID 标签筛选。电脑使用独立标签和生命周期；试点准备核对固定电脑镜像没有该命名空间的标签。电脑任务结束不会由临时沙箱回收器删除本人实例或工作盘。
