# 构建工作台图片与输入布局修复

发布版本：20260908-083442。

截图中的失败不是上传失败：文件已上传，能力目录中的 glm-5-3-flash 被登记为纯文本模型，缺少 vision 标记（模型本身支持视觉，已在 20260908-101112 版本纠正）。旧界面又只在发送后的消息中显示文件名，造成无法看图的体验。

## 修复

- 试跑在提交运行前，按当前租户可见能力、运行协议、所需能力和有效凭据选择视觉模型。原模型支持时保留原模型；否则使用兼容视觉模型。没有可用模型时直接提示，前端保留输入与附件。后续对话继续使用本会话选择的模型；回答上方展示实际模型。
- 两侧附件与主对话共用 MessageAttachmentView：发送前后均有缩略图、原图弹层、下载和 Escape 关闭。使用同源、校验文件归属的内容地址，避免发送后撤销临时 URL 导致图片丢失。
- 左侧不再因附件存在而强制试跑，也不再在创建后把附件移到右侧。文本、PDF、Office 材料通过已有解析器读取，图片通过视觉模型整理为构建参考；创建时作为参考输入，修改时进入构建对话上下文。解析失败时保留附件与输入。材料作为数据处理，配置改动仍走预览与应用。
- 修复全局 composer 样式覆盖分栏宽度、align-items 将附件推向右侧的问题。两侧保持 100px 基础高度、14px 外侧留白，文本和工具栏在各自分栏内。多附件区域最多 140px，独立滚动；总高度受视口限制，输入和发送控件保持可见。
- 对话正文、代码和表格限制在分栏宽度内；处理信息仍在正文上方，执行详情默认折叠。
