## 独立项目整理与统一执行（r20 候选）

按最新布局方案，项目恢复为业务整理入口，执行继续复用主对话：

- 项目名称进入独立首页；概览、任务、资料、成果四个页签分别处理推进、筛选、资料维护与跨任务产物。
- 项目任务通过现有持久任务接口创建后进入 `/?thread=…`，主对话保留项目面包屑，切换执行智能体时继承项目归属。
- 右栏继续提供资源快捷入口；项目管理业务约定、事实与资料，通用指令、工具、技能定义和发布版本仍在智能体工作台维护。
- 成果包含归档任务的来源与下载；只有明确加入项目资料后才成为后续输入。成果页展示最近 500 项，任务支持服务端项目筛选与分页。
- 项目知识合并时保留智能体自带知识，再追加项目与本轮选择。

运行边界与可追溯性：

- `ExecutionIdentity.business_project_id` 独立承载业务项目；旧 `project_id` 保留凭据与服务令牌的兼容语义。
- 自动提取、关键词/向量检索、按 ID 读取、去重与纠正均校验业务项目。旧记忆不推断归属、不自动搬迁，也不进入项目运行。
- 新记忆令牌追加业务项目 claim，并继续接受旧格式令牌；后台提取使用来源 Run 的冻结项目坐标，移动任务不会改写历史作用域。
- 附加技能在 Run 创建时固定内容与哈希，复用租户隔离的内容寻址对象存储；Worker 从快照执行，目录升级不改变已创建 Run。失效与不兼容引用明确拒绝。
- `context_manifest` 保存智能体坐标、项目设置与事实版本、文件哈希、知识快照、技能来源；`project.skills.staged` 记录实际冲突决策，智能体自带技能优先。
- 任务详情中的「本次生效资源」按需读取受所有权保护的上下文接口，显示来源、固定版本与同名冲突结果。
