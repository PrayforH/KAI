# 174 思考行与过程连续性修复（2026-09-16）

## 问题与修复

- 长思考文本参与网格列的最小宽度计算，撑大过程区并压缩“思考”标签。现在过程网格使用 `minmax(0, 1fr)`，逐层约束最小宽度；标签与分隔点禁止收缩，预览在剩余宽度内单行裁剪。
- 思考行默认收起，形式为“思考 · 内容”。同一个 DOM 节点持续追加文字，内容超长后滚动到尾部；点击可展开全文，后续流式更新保留手动展开状态。
- 个人设置中的“详细执行过程”控制工具逐项展示，不再自动展开思考全文。
- 中间说明此前只在后续工具开始后进入过程区；新的思考块不作为分界，造成说明暂时消失。现在工具、子任务和新的思考块均可确认前文是过程说明；先发布可持久展示的过程，再隐藏临时答复文本。
