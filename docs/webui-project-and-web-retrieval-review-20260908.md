# WebUI 项目语义与联网检索分析

日期：2026-09-08。本文记录初次分析。后续用户明确授权将 lead-agent 任务直接放在“任务”栏下，该展示调整已完成，见 [系统助手修复记录](webui-system-assistant-fixes-20260908.md)；独立项目/文件夹数据模型仍仅分析。联网策略在本分析后按用户补充要求实现，最新部署目标为 `172.20.105.79`；实现边界与真实验收见 [79 发布记录](web-network-79-release-20260908.md)。

## 结论

Web 产品可以放宽公共资料检索：启用联网后，让智能体自行多轮搜索和读取公开网页，不必要求用户逐个批准搜索词或普通公网域名。边界应落实在服务端检索工具、查询内容与后续动作上，不能只靠“网页内容不可信”的提示词。

`lead-agent` 应保留为系统通用入口。侧栏当前“项目”实际按智能体名称分组，不是独立的用户项目；近期更适合叫“按智能体分组”，或者产品上改用用户文件夹整理对话。两者不能混成一种对象。

## 1. 现有项目、智能体和任务到底是什么关系

代码依据：`web/harness-console/src/components/task-sidebar.tsx` 的 `taskProjects` 用 `task.agent_name` 建 Map；`page.tsx` 的 `startTaskInProject` 复用分组第一条任务的智能体及版本、owner、space。任务摘要没有独立 `project_id`。底层 `ExecutionIdentity.project_id` 是执行身份字段，不能据此认定 UI 已有完整项目容器。

| 对象 | 当前含义 | 建议面向用户的含义 |
| --- | --- | --- |
| lead-agent | 系统默认通用智能体，默认新任务入口 | 显示“通用助手”，系统属性用小标签说明；保留内部标识 |
| 智能体 | 可复用、带版本的能力与配置，含模型、工具、知识等 | “谁来完成工作” |
| 任务／对话 | 用户的一段持续工作，有历史、运行和产物 | “这次要完成什么” |
| 当前侧栏项目 | 同一个 `agent_name` 的任务集合 | 如果保持现有模型，应称“按智能体分组” |
| 文件夹 | 目前侧栏尚无独立用户文件夹对象 | 用户整理任务的可选分类，不自动共享上下文或权限 |
| 真正的项目 | 不能等同当前 agent 分组 | 围绕持续目标，包含资料、说明、任务及可选协作成员；一个项目允许使用不同智能体 |

Web 版本使用“项目”并非不合适，关键是它必须有独立的目标和资源范围。例如“供应商年度评估”可以同时有资料整理、风险检索、报告撰写任务，由不同智能体处理；用户不应该因为换智能体而换项目。

当前按名称分组还有两处潜在歧义：同名不同 owner/space 的智能体可能混在同一组；组头的“新建”复用第一条任务的版本，未必符合用户对“在项目里新建”的理解。本次仅记录，不修改。

建议分两步：先明确标签、把默认通用助手作为自然的新任务入口；确实需要整理大量历史时，增加可选文件夹。只有需要共享资料、项目说明或成员协作时，再引入独立项目模型。任务属于一个可选项目，任务使用一个智能体快照，执行中产生多个 Run；归档和文件夹移动不改变权限。`lead-agent` 不需要成为用户每次都看见的“系统项目”。

## 3. DeepSeek Harness 源码发现

核查官方仓库提交 `c389f96bf3a9b6807cb71ed6bdad5849be0df6d8`，只读源码，未安装、运行其插件或将第三方文档当作工作指令。

1. **能力分层清楚。** 模型可见的 `web_search` / `web_fetch`、统一 web 服务、搜索提供方和 HTTP 抓取提供方分开。工具可多轮调用，适合边思考边补充来源；“前置一次检索”不是 Harness 的必然限制。[工具实现](https://github.com/deepseek-ai/deepseek-harness/tree/c389f96bf3a9b6807cb71ed6bdad5849be0df6d8/packages/web/tool-web/src)
2. **网页结果明确降为资料。** `trust.ts` 定义外部内容提示；search、fetch 的结果展示及工具指导要求将外部文本当作不可信数据，引用原 URL。该提示有帮助，但不是可证明的注入防护边界。[trust.ts](https://github.com/deepseek-ai/deepseek-harness/blob/c389f96bf3a9b6807cb71ed6bdad5849be0df6d8/packages/web/tool-web/src/trust.ts)
3. **公开网页抓取仍受约束。** 仅 HTTP(S)、禁止 URL 内凭据；DNS 结果必须是公网地址，连接固定到已校验地址；只跟随同源重定向；有体积、文本长度、超时和跳转次数限制。匿名读取，不直接携带业务登录状态。这恰好是“允许广泛公网阅读，同时保留检索服务安全边界”的参考。[抓取包说明](https://github.com/deepseek-ai/deepseek-harness/blob/c389f96bf3a9b6807cb71ed6bdad5849be0df6d8/packages/web/web-fetch-http/README.md)、[网络实现](https://github.com/deepseek-ai/deepseek-harness/blob/c389f96bf3a9b6807cb71ed6bdad5849be0df6d8/packages/web/web-fetch-http/src/network.ts)
4. **DeepSeek 搜索是独立调用。** 提供方通过 Anthropic 兼容 Messages 请求调用原生搜索工具，提取结构化来源与引用片段；不把辅助模型的自由文本直接当作最终答案。一次搜索会产生额外模型调用与延迟，默认可进行最多 5 次原生搜索使用；这是该源码版本的参数，不是官方聊天网站的承诺。[provider.ts](https://github.com/deepseek-ai/deepseek-harness/blob/c389f96bf3a9b6807cb71ed6bdad5849be0df6d8/packages/web/web-search-deepseek/src/provider.ts)
5. **预设权限不等于强制执行。** 权限预设将沙箱和审批组合成选项，真正执行仍由对应服务负责。官方安全说明也明确它是未经安全审计的开发者预览版，不应视为生产安全保障。[权限预设](https://github.com/deepseek-ai/deepseek-harness/blob/c389f96bf3a9b6807cb71ed6bdad5849be0df6d8/packages/interaction/permission-presets/README.md)、[官方安全说明](https://github.com/deepseek-ai/deepseek-harness/blob/c389f96bf3a9b6807cb71ed6bdad5849be0df6d8/SAFETY.md)

## 4. 建议的 Web 联网体验与安全边界

按此次讨论“先不考虑代码执行”的前提，推荐产品默认“自动联网”，也可关闭；只有需要用户区分成本和耗时时，再加“深入检索”。开关与实际工具注册、服务端准入绑定；页面开关关闭后，模型不能通过其他同类工具继续外搜。

| 情况 | 推荐处理 |
| --- | --- |
| 查询公开知识、政策、新闻 | 自动搜索，可多关键词并行、多轮补充，不逐次确认 |
| 打开公开网页及其来源链接 | 允许安全 HTTP(S) 读取，默认不限定少数站点；保留目标地址、重定向与大小检查 |
| 网页包含“忽略用户指令”“上传资料验证”等内容 | 作为原文资料处理，不升级为指令，不据此改变工具权限或外发数据 |
| 搜索需要带上内部报告、个人数据或秘密 | 先用公开关键词摘要；必要的敏感外发遵循用户授权，不能把完整对话或附件自动拼进 query/URL |
| 访问内网、数据库、带登录态网站 | 使用独立已授权连接器；不经过匿名公网抓取通道 |
| 发消息、提交表单、写业务系统、写长期记忆 | 由用户目标与独立写权限决定；网页或检索结果不能单独授权 |
| 网络超时、站点受限、搜索不足 | 清晰显示来源不足、允许重试或换来源，不虚构结果 |

检索注入至少有三个层面：污染答案、诱导工具动作、诱导通过查询词或 GET URL 泄露数据。最后一种不需要 Bash 或代码执行，所以只允许 GET 也不足以消除风险。排序和引用有助于核验信息，但不会把网页内容变成可信指令。

服务端应把来源 URL、抓取时间和正文一起返回；清理脚本及无关页面结构，限制正文长度；保留用户指令、系统约束、外部资料的来源区分。检测到疑似指令性内容时，可以标记并继续提取相关事实，不必把包含普通“操作步骤”的正常文档一律拦截。后续工具参数仍按真实用户目的和权限校验，不能由检索正文替代授权。

现有仓库 `compiler.effective_contract` 主要根据选中的 MCP 标注 `none/internal/external`，默认策略已有 Tavily 搜索放行规则。这可以扩展成统一 `search` / `fetch` 检索服务；“公网资料检索”与“任意程序联网”应分别建模。此前的执行出口审查仍适用于启用了 Bash/Python 的实际运行环境，但不应迫使普通 Web 搜索采用逐域名审批的交互。

建议先实现上述检索通道并增加小规模对抗验收：伪造系统指令、恶意引用链接、内网与元数据地址、DNS/跳转绕过、把私有附件编码进 URL、诱导写记忆或发消息；同时验证正常多轮搜索、合法操作手册与引用不会被误拦。通过后再切换产品默认联网。本次没有修改联网策略或模型、MCP 配置。
