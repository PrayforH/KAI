# 助理连续消息与实时状态

实现提交1f9e968d、f053821c、7253a3a3。仅部署79；保留32.45和云电脑绑定、聊天、配置及文件。此前HTML跨渠道附件缺口不包含在本次改动，仍见单独调查报告。

## 问题和处理

前端原来每次等消费回执轮询完成才允许投递下一条，增加连发延迟；运行结束时明确未投递也被当作不确定状态暂停。现按消息顺序串行写入请求，后台独立核对回执，不逐条等待消费确认。明确未投递的消息继续为下一轮，不确定写入保留、不自动重复，也不阻止后来的不同消息。

SDK旧路径只query追加输入。助理面现在使用ClaudeSDKClient.interrupt，中断当前回复，消费中断结果后在同一会话query补充；一批消息共用一次中断。这个控制边界不作为平台Run失败；真实SDK失败继续返回。自然结果到达时再读一次持久化inbox，避免250ms轮询间隙漏投。普通任务／项目交互策略仍保留；此控制不会回滚已经完成的工具副作用，也不绕过平台权限或租约。Warm连接的interrupt同样先验证执行归属。

聊天去掉接收／核对提示、重新发送按钮、附件排队说明和传输队列报错。已接收补充按原始requested序号与公开回复合并，不按延后的回执顺序展示；刷新重放保持相同顺序。实时状态由会话尾部唯一渲染，位于最新发送消息下方，旧回复不留重复状态。

状态短语按实际动作区分读取控件、查找窗口、点击、填写、按键、滚动、创建助理、发送助理消息、检查凭证等；本地电脑不再误称云电脑。只读取工具名和allowlist action枚举，不展示填写内容、密码、命令、URL或控件ref；电脑返回的协议详情不作为状态文案。不凭时间编造工作阶段或宣布结果成功。
