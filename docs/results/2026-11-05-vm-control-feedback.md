# VM 控制权与操作提示修复

用户反馈本人控制缺少按钮、助理被阻止却没有现场提示；追加要求正常使用 VM，仅明确需要时使用本地电脑。

原因：查看目标与执行目标可独立变化，旧界面在查看其他电脑时隐藏了所有控制权动作，同时丢掉实际执行电脑的 human/pending 状态。控制权 POST 非成功响应直接返回，用户看不到失败原因；慢轮询也可能覆盖刚完成的交还状态。

修复：分别保留执行电脑权威状态与当前画面的输入状态。常驻取得控制权、交还助理或取消接管动作；查看另一台电脑时显示原电脑占用及交还动作，并将显式“供助理使用”移出更多菜单。断线仍可交还，交接须经服务端确认才开启输入。状态读取失败立即暂停本地输入并显示重试提示；控制权请求失败、目标变化和切换失败均有可读反馈。操作版本阻止早发晚到的轮询恢复旧控制权。仍校验实际执行目标的 binding，不跳过服务端空闲切换、epoch 或所有者检查。

正常执行使用云电脑。仅查看本地电脑不切换执行目标；显式将本地电脑设为“供助理使用”才切换本地执行。页面标明该约定。现场已通过已有页面先交还本地控制权，再显式切回 cloud；数据库只读核对 provider=vm-computer、原 VM 卷保留、desktop=observe。没有使用关键词猜测设备或按 Bot 名称自动选择本地。

验证：computer-selection 与 desktop-occupancy-chip 两个文件共19项测试通过，覆盖异地查看时交还正确 binding、断线交还、409/503失败提示、pending取消、状态读取失败禁输入及旧轮询不覆盖交还。tsc --noEmit、git diff --check通过。

发布候选从79当前 Web 530f1bae 构建，仅覆盖 computer-desktop.tsx 和对应局部 CSS；没有顺带部署尚未发布的 Bot 目录投影或 API。API、Worker、Control、Viewer、IM与之前 init:true 进程回收配置保留。现场发布与页面验收结果另补。

## 79 实际发布与验收

Web镜像 kai/superagent-web:20261105-desktop-controls，ID sha256:5ae6bfbe943126c9f4afeb2170dc10509aef40c4c8c773b1313fcdfbe9040517；Compose SHA256=d45ae38be3a5f389ba12bb6758a492221c1291b0e7ac0dacb8b4d600dfb91eca。只重建Web，保留原API/Worker/Control/Viewer/飞书/微信及其他容器ID，Nginx仅reload。节点回执 /data/kai-desktop-controls-20261105/release.json。

真实Chrome刷新79并打开电脑面板：云电脑显示已连接；“取得控制权”后服务端确认human，页面显示“由你控制”及“交还助理”和键鼠操作说明。随后仅切换查看本地电脑，没有切换执行；页面显示“当前仅观看本地电脑；助理使用的是云电脑”、原云电脑由你控制，以及“交还云电脑”按钮。通过该按钮交还后原占用提示消失，再切回云电脑显示已连接、仅观看及可用“取得控制权”。未发送业务聊天、未向本地电脑输入、未改用户文件。最后只读核对canonical provider=vm-computer、desktop=observe、epoch232；平台默认配置同样为vm-computer。

这是明确选择执行电脑的策略：当前选择恢复VM，查看本地不触发选择；仍支持用户明确选用本地电脑。没有引入自然语言分类器，也未将该策略虚称为逐条消息自动判断或一次性授权到期机制。状态读取/409/503异常通过前述受控测试验证，未在79人为制造网络故障。
