# 桌面产物统一回到任务工作区：79 发布与验收

桌面应用将交付文件保存到 `~/deliver`，`computer_export_file(path, name?)` 将其复制到任务工作区 `outputs/desktop/`。随后沿用已有 ComputerWorkspace 收集、分块回传、摘要校验、artifact 发布及附件预览。文本与二进制不分两套流程，不让模型通过聊天编码或临时 HTTP 服务搬运文件。

## 实现边界

- 工具仅对已开启原生桌面能力的 VM 提供；未宣称旧本地客户端已具备这座桥。新镜像安装清单、既有 VM 维护清单和桌面准备步骤同时包含模块及私有交付目录。
- 复用当前电脑绑定、执行租约、桌面控制代次、动作锁、接管拒绝与取消排空。导出先初始化任务工作区并捕获基线；一般 GUI 操作仍不触发工作盘扫描。
- 只接受交付目录下的相对路径及可选文件名，最大 64 MiB。逐级持有目录描述符、拒绝软链接和非普通文件，源文件必须属于桌面账号且仅有一个硬链接；复制时检查租约、大小与源文件稳定性。
- 受控入口只跨账号打开明确的源文件；写工作盘时切到任务有效 UID/GID 并清空附加组，仅租约检查临时恢复有效 root 身份，退出时恢复原身份。独立 gate 进程不运行任务代码、加载用户模块或执行外部程序。避免 root 写 9P 共享盘失败，不修改桌面 HOME、profile 或目录权限。
- 工作区私有暂存、原子创建，不覆盖不同内容的同名文件；重复导出相同文件可幂等返回。结果仅含路径、字节数和 SHA-256，内容通过已有文件面回传。

## 真实验收发现并修正的问题

第一轮真实模型验收 `run_8de0ab09b4fd4fa9b310404d054b9a0f` 创建了合成文本和 MP4，但导出失败。普通桌面调用正常，原有 gate 将文件系统异常统一映射为租约拒绝，导致模型误判为另一个 holder 占用。不能把该轮或服务 healthy 记为成功。

维护探测确认 root 写共享工作盘得到 `PermissionError(errno=1)`。修正为上述任务身份写入后，同一份已存在的 62 字节文本成功复制且摘要一致。补充的 gate 诊断仅记录异常类型、errno 和固定原因码，不记录命令、文件内容、路径或凭证。最终成功以随后的正常模型工具流和网页验收为准，而非维护探测。
