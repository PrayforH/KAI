# 174 「自动化」模块发布（2026-09-19）

本次发布在 174 环境上线一级导航模块「自动化」：定时任务（含 12 个模板、添加/编辑弹窗、
立即执行、暂停/恢复、删除）与运行记录（筛选/搜索/刷新、状态徽标），深浅两套主题全部走
`--codex-*` 语义 token。

## 代码变更（feature/automation → develop）

- `src/harness/automations/`：新领域。`AutomationTask`/`AutomationRunRecord` 模型、
  五字段 cron 求值器（支持 `*/n`、范围、星期别名、时区）、服务层（CRUD、
  `dispatch_due` 原子认领防重发、手动执行、记录状态按 Run 终态推导）。
- 执行链路：到点/手动创建 workload Session + Run（与 AGUI 一致，按任务 owner 的
  最新 published agent 版本钉版本，可用 `HARNESS_AUTOMATION_AGENT_VERSION` 覆盖，
  亦兼容 `HARNESS_AGENT_NAME`/`HARNESS_AGENT_VERSION` 别名），由 worker 队列执行；
  单进程本地部署可注入 inline executor。
- 存储：`automation_tasks`/`automation_records` 两张表，迁移 `0034_automations`。
- 路由：`/v1/studio/automations`（列表/创建/更新/enable/pause/run/删除/next-runs/records），
  经 Next BFF `/api/studio/*` 代理。
- 前端：`/studio/automation` 页面 + `AutomationManager` 组件；左侧导航「自动化」位于
  插件（技能/MCP）之上；模板预填、必填校验红描边、下次执行预览、删除二次确认。
- 测试：后端 19 项单测（cron 求值 + 服务调度），前端 111 个测试文件全绿（含
  `tests/automation-manager.spec.ts`）。

   同库中 id=10/11 的 token key 同样失效。

1. new-api `tokens.id=12` 的 `model_limits` 追加 `deepseek-v4-flash`

## 主页左侧任务列表信息架构调整（2026-09-19，3501 已上线）

**原结构问题**（`task-sidebar.tsx`）：分组维度是**执行者**，且默认智能体被特殊化——

```
taskProjects = 按 task.agent_name 分组（“项目”名是英文 agent_name）
├─ 「任务」区   ← 只放 agent_name === "lead-agent"
└─ 「智能体」区 ← 其余每个智能体一个文件夹
```

具体问题：① 导航「智能体」与列表「智能体」同词不同义；② `lead-agent` 的任务被单独
归入「任务」而其它智能体归「智能体」，用户无法理解为何分两处；③ 分组标题是
`lead-agent` / `public-opinion-agent` 等英文名（已有 `agentDisplayName()` 却未使用）；
④ 没有时间维度，找不到"刚做过的"，置顶也只在各自分组内浮顶。

**主流对照**：ChatGPT/Claude 均为「最近(时间桶) + 项目(用户自建容器)」，执行者不做分组；
Cursor/Devin/Manus 以项目/工作区为顶层容器；Linear/Notion/飞书 是「项目 + 事项」加横切视图；
国内 Chat 类把智能体当入口而非任务分组。

### 侧栏「项目 + 任务」合并为一个滚动列（2026-09-20，已上线）

**现象**：项目区与任务区之间出现巨大留白，需要各自滚动。

**根因**：侧栏 `.task-sidebar` 是**固定行数的 CSS 网格**
（`grid-template-rows: auto auto auto auto minmax(0,1fr) auto`，共 6 行）。
加入「项目」「任务」两组后子元素变为 7 个，第 5 行（`minmax(0,1fr)`）被**项目列表**
吃掉并撑满，任务区被挤到隐式行里贴底。

**修复**：

- 新增 `.task-list-scroll` 包裹「项目头部 + 项目列表 + 任务头部 + 任务列表 + 空/加载/错误态」，
  侧栏恢复为 6 个子元素；该容器 `min-height: 0; overflow-y: auto; overscroll-behavior: contain`，
  两区**同步滚动**，项目收起时任务自然上移（实测收起/展开 任务标签 366px ↔ 396px，正好一行）。
- 统一左缘：`.task-project-heading` 与 `.task-list-item` 的 `padding-left` 统一为 12px，
  任务文字与项目名对齐（实测 45px ↔ 47px），不再出现任务比项目深一截。
- 新增 `tests/task-projects.spec.ts` 两条回归断言（单一滚动容器、左缘统一）。

**验证**（3501，深色 + 浅色）：两区相邻无留白、缩进对齐、开合时任务随之上移；
前端 114 个测试文件 741 项全过。
