# 174 「自动化」模块发布（2026-09-19）

本次发布在 174 环境上线一级导航模块「自动化」：定时任务（含 12 个模板、添加/编辑弹窗、
立即执行、暂停/恢复、删除）与运行记录（筛选/搜索/刷新、状态徽标），深浅两套主题全部走
`--codex-*` 语义 token。

## 代码变更（feature/automation → develop）

- `src/harness/automations/`：新领域。`AutomationTask`/`AutomationRunRecord` 模型、
  五字段 cron 求值器（支持 `*/n`、范围、星期别名、时区）、服务层（CRUD、
  `dispatch_due` 原子认领防重发、手动执行、记录状态按 Run 终态推导）。
- 执行链路：到点/手动创建 workload Session + Run（与 AGUI 一致，按任务 owner 的
  最新 published agent 版本钉版本，可用 `HARNESS_AUTOMATION_AGENT_VERSION` 覆盖，
  亦兼容 `HARNESS_AGENT_NAME`/`HARNESS_AGENT_VERSION` 别名），由 worker 队列执行；
  单进程本地部署可注入 inline executor。
- 存储：`automation_tasks`/`automation_records` 两张表，迁移 `0034_automations`。
- 路由：`/v1/studio/automations`（列表/创建/更新/enable/pause/run/删除/next-runs/records），
  经 Next BFF `/api/studio/*` 代理。
- 前端：`/studio/automation` 页面 + `AutomationManager` 组件；左侧导航「自动化」位于
  插件（技能/MCP）之上；模板预填、必填校验红描边、下次执行预览、删除二次确认。
- 测试：后端 19 项单测（cron 求值 + 服务调度），前端 111 个测试文件全绿（含
  `tests/automation-manager.spec.ts`）。

## 模型路由凭据故障修复（2026-09-19，已上线验证）

**现象**：用户任务「每日 AI 新闻推送」（模型 `deepseek-v4-flash`）执行失败，
运行记录 `runtime_result_error / api_error_401`。

**根因链**（逐层排除得出）：

1. 路由 `deepseek-v4-flash` 的 `baseUrl` 是 174 本机的 new-api 网关
   `http://172.20.109.174:4000/v1`（不是另一台 172.20.109.112）。
2. 该网关的 token `agent-studio-deepseek`（id=12）**认证通过**（返回 403 而非
   401），但其 `model_limits` 只允许 `deepseek-flash,deepseek-v4-pro`，
   而平台发送的模型名是 `deepseek-v4-flash` → 被网关拒绝。
3. 平台凭据库里该路由存的是另一把已失效的 key（401 invalid credentials），
   同库中 id=10/11 的 token key 同样失效。

**修复动作**（均可回滚）：

1. new-api `tokens.id=12` 的 `model_limits` 追加 `deepseek-v4-flash`
   （原值备份在下方命令中）。
2. 平台凭据库 `local / tenant:model-control-plane / deepseek-v4-flash` 更新为
   该网关实际接受的 token（revision 7）。
3. 顺带修复 `deepseek-v4-pro`：其 baseUrl 是 172.20.109.112:31300，原凭据 401，
   更新为 `HARNESS_NEW_API_KEY`（实测 200，连续 5 次调用均成功）。

**验证**：用户任务手动执行成功（27 秒），结果摘要为当日真实 AI 新闻简报；
两条路由单独探测均 200。

**回滚**：

```bash
# 恢复 token 模型白名单
docker exec postgres-newapi psql -U root -d new-api \
  -c "update tokens set model_limits='deepseek-flash,deepseek-v4-pro' where id=12;"
# 恢复凭据（修复前快照）
docker exec agent-studio-174-postgres-1 psql -U harness -d harness \
  -c "select count(*) from mcp_credentials_backup_20260919;"
```

**遗留**：`glm-5-3-flash`、`shdata-model` 两条路由未在本轮验证；模型选择器应改为
读取平台能力目录（而非前端硬编码常量），以便只展示平台真实注册且可用的路由。
