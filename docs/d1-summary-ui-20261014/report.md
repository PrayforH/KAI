# 结果驱动的 Intelligent UI 摘要展示

2026-10-14。代码版本 b52ea7f0；174 与 79 均部署 API/Worker `summary-ui-20261014-r6`、Web `summary-ui-20261014-r5`，服务健康。

## 选择方式

先让主模型完成真实查询，再由 d1-3B 根据当前用户请求、已获得的数据和可用渲染能力选择文字、摘要、表格、图表或比较。候选形式从统一能力目录获得，只包含可由已有数据构成的形式；分类器不生成事实。带应用操作的组件沿用原流程。普通回答中的结构化表格和连续标签事实也能成为候选，不要求主模型总是输出组件协议。

没有增加天气、订单、航班等业务关键字分支。数据缺失、无可用候选、超时和无效输出沿用可读降级路径。发布时间和来源只能来自原资料，不补造时间或来源。

## 卡片布局

此前重用指标网格会把整段描述放大加粗、铺满四列。摘要现在使用独立事实布局：主要信息居前，短值突出，长描述正常字号；次要信息两列排列，窄屏单列；最大宽度 600px，来源保持可访问。指标组件本身保持原行为。Chrome 中核验了既有天气对话从历史恢复后的新版卡片。

## 实测

全部使用自然提问，没有追加 HTML 或组件格式指令。79 完成实际联网天气查询。

- 上海今天的天气怎么样？：d1 选择摘要；来自回答中的真实查询事实；流式发布与历史恢复一致。
- 上海未来一周最高温和最低温的变化怎么样？：d1 选择折线图；数据保持原查询的日期与温度；流式与历史一致。
- 只用一句话告诉我上海今天的天气。：文字，没有卡片或 HTML。
- 明天上海会下雨吗？：回答先给出结论，d1 仍保留了主模型提供的未来几日明细表。该次未达到预期的纯文字负例，不作为通过记录。说明小模型对是非问句的简洁优先判断仍有局限。

测试记录见 weather-acceptance.json；天气数值是验收快照，不作为持续更新预报。
