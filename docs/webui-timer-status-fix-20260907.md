# WebUI 计时与任务错误提示修复

状态：本地实现与验证，未部署。目标前端为近期 3501 发布记录中的 `web/harness-console`。

## 行为

- 新 Run 使用独立计时起点，零耗时显示 `0s`。不再用浏览器时间减服务端 `started_at`，避免服务端与浏览器相差约 40 秒时把偏差计入耗时。
- 同一 Run 的本地计时起点按 Run ID 保存。组件卸载、任务切换、重连和同一标签页刷新后可接续；最多保留 128 个起点。
- 服务端事件给出更大的耗时时，重建本地基准继续递增；完成、失败、取消或拒绝后立即使用最终事件耗时并停止计时。
- 任务侧栏增加错误圆点与可见文字：处理错误、已超时、已拒绝。已打开任务也保留错误提示；增加读屏状态和悬停说明。
- 当前任务与实时 Run ID 匹配时，实时失败立即反映到侧栏；旧 Run 的失败不覆盖重试后的新 Run。取消中和服务端超时状态保留。

## 实现范围

计时逻辑在 `src/lib/run-elapsed.ts`，显示接入 `src/components/activity-summary.tsx`；侧栏变更在 `src/components/task-sidebar.tsx` 与 `src/app/web-codex.css`（以上相对 `web/harness-console`）。不修改后端时间戳、历史 Run、智能体发布版本或权限。

首次在没有本地起点的浏览器打开既有运行时，以最近服务端事件的耗时建立基准；现有协议没有快照生成时间，因此不能精确补算最后一个事件之后的静默时间。禁用浏览器存储时，当前页面内切换仍能接续，刷新恢复退回服务端事件基准。
