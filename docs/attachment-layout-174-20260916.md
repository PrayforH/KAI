# 174 输入区附件布局修复

2026-09-16 已发布 `kai/axis-web:attachment-layout-20260916`。

## 原因与修改

线上 `composer-file-card` 将附件外层设为 78px，但组件库内层卡片仍为 48px，
同时增加底部 padding，导致缩略图溢出、上传状态落到卡片边框外。
输入框改为纵向布局后，附件列表还沿用旧的百分比 flex-basis。

- 附件列表使用自然高度，顶部留出 12px，保留横向滚动。
- 卡片与内容统一为 76px 高、232px 宽，预览固定为 36px。
- 文件名单行省略，为卡片内的删除按钮预留空间。
- 上传文字及进度条放在卡片内部，保留错误状态颜色和上传进度。

仅修改 `conversation-experience.css`。线上源代码与本地已有其他改动不同，
发布基于上一版线上源代码应用独立 CSS 增量，没有覆盖其他功能。

- 使用线上完整 CSS 和附件 DOM 结构在 Chromium 中检查 800px、452px、312px 宽的输入框。
  卡片和内容高度一致；缩略图、状态和删除按钮均在卡片内，文件名不与删除按钮重叠，页面无横向溢出。

- 发布前活动运行为空，正式前端健康检查通过，3501 返回 200；正式返回的 CSS 已包含新规则。
- 本次未通过真实会话上传文件；验证针对布局，没有修改上传行为。
