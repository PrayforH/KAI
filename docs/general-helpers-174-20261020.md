# 通用助手预置子智能体与对话内协作展示

## 功能与边界

通用助手发布版本升级为 `1.1.1+platform.99dfe677`。新任务直接获得三个内部角色，无需用户先在智能体空间创建或逐个选择：

| 角色 | 职责 | 工具范围 |
| --- | --- | --- |
| researcher · 资料研究 | 阅读材料、公开资料研究、来源整理 | Read / Glob / Grep / WebSearch / WebFetch |
| analyst · 分析执行 | 数据计算、独立产物制作及验证 | Read / Glob / Grep / Write / Edit / Bash |
| reviewer · 结果核验 | 事实一致性、遗漏、矛盾和交付要求检查 | Read / Glob / Grep |

主助手在复杂任务有独立工作时主动委派；简单问答和单步执行自行完成。有依赖的核验等待上游产物。子任务使用独立写入路径，完成后由主助手汇总。平台继续限制一层 Lead/Sub、并发与任务数量，不启用 Agent Teams。

这些版本按用户隔离并采用正常的稳定身份注册，但标记为 `visibility: internal`、`managed-by: platform-default`，不创建 Studio 草稿，不进入普通任务选择器。不会枚举、自动绑定或改写用户自建智能体。三个子角色的版本先发布，再发布引用它们的主助手。重试保持幂等，同名同版本内容冲突会拒绝覆盖。

项目继续承载指令、文件、知识库、MCP 和成果。预置角色不会自动继承项目连接器和知识库凭据：由主助手按当前权限获取必要内容，传入委派材料或工作区文件。用户自建的专用协作关系仍在智能体空间配置和发布。

已有会话保持原版本；刷新页面后新建通用助手任务即可使用新配置。

工作材料使用 `materials/`，产物使用 `outputs/`。`inputs/` 属于平台每轮重新挂载的原始上传区，不用于生成跨轮工作材料。主助手委派前确认文件存在；子任务只进行一次有针对性的缺失文件查找，仍找不到则返回缺口。

## 对话区

执行过程内增加一组「子智能体协作」：角色、分工、执行中/待审批/完成/失败状态和耗时。每项可展开查看分工、最近工具和返回结果；整体可收起，历史回放使用相同的持久化事件。

后台 Agent 工具返回的启动回执不代表子任务完成。显示以 `subagent.started/completed/failed` 为准；停止后的未完成任务显示「已停止」，终态缺少子任务完成证据显示「未确认完成」。保留用户主动折叠选择，详情仅渲染文本并沿用会话脱敏。

参考 [Claude Code 子智能体文档](https://code.claude.com/docs/en/sub-agents) 的按职责委派、同一会话内观察任务和后台结果通知方式。展示沿用本项目的字体、色彩和对话布局，没有增加页面或改变左侧导航。
