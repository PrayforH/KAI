## 范围与接入

在现有助理设置中增加微信卡片，点击「连接微信」生成二维码，使用本人微信扫码并在手机确认。扫码身份只绑定当前登录的 KAI 账号。支持二维码过期刷新、手机配对码、连接状态、诊断与断开；不要求填写 App ID 或 Secret。

首版仅处理绑定本人的助理私聊文字。图片、语音、文件会明确提示暂只支持文字，不假装已分析附件。所有渠道通过同一个 `PersonalConversation` 服务进入 `kai-personal-assistant-v1`，微信不另建助理线程。

实现依据为 [腾讯开源微信通道](https://github.com/Tencent/openclaw-weixin) 的 [HTTP 协议说明](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)。KAI 直接适配 iLink HTTPS 二维码登录、长轮询和文字回复，没有安装额外 OpenClaw 执行环境。协议文档本身说明类型字段不等于完整服务端契约，实际账号授权和消息能力仍须真实扫码验证。

## 持久化与隔离

新增迁移 `0048`，仅增加微信连接及消息队列表，不覆盖原有数据。Bot token、扫码临时数据、接收游标和回复上下文令牌使用现有 AES-GCM 凭据服务加密保存；不会回传 Bot token。二维码只向本人网页登录展示，API Key 无法生成或读取配对码。

专用接收器以数据库锁保证只有一个部署实例消费；按账号分别长轮询、处理队列。先持久化消息并同事务保存游标，以 Bot＋消息 ID 去重；创建模型 Run 使用稳定幂等键，重启后继续等待原 Run。其他发送者、群聊及机器人消息不进入个人会话。同一 Bot 不能同时绑定不同 KAI 账号。

断开或重新扫码改变的连接不会接收旧轮询结果；权限在提交模型和回复前再次核对。发送前持久化状态，网络结果不明确或进程中断时标记未确认，不自动重复发送并宣称成功。
