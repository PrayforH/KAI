# Computer V1 前置：保留工作盘的镜像升级

2026-10-27，北京时间。实现提交 `6c1cf774`，接续[传输优化](assistant-computer-transfer-20261027.md)。本轮完成升级底座及 79 隔离电脑实测；正式助理仍运行 r21、数据库 0051，没有切换本人电脑镜像。浏览器桌面、观察与人工接管尚未完成。

## 升级契约

新增 `ComputerManager.migrate_image(tenant, user, expected_image=...)`，目标取自驱动的固定 image ID。普通 `ready()` 仍拒绝配置与现有镜像不一致，不会因为改了环境变量就删除当前电脑。

1. 内部节点验证固定 `sha256:` 目标已安装且有受支持的监督器标记。只读取镜像信息；错误目标和不明确的回执不会先改变电脑状态。
2. 持有恢复租约并在数据库锁内比较源镜像。已有活动任务、镜像已被其他操作改变时拒绝；不会抢走未过期执行权。
3. 节点在物理生命周期互斥锁内重新验证租约、本人账号及个人会话、目标配置。只按已核对所有权、卷和进程配置的不可变容器 ID 删除旧实例，不删除工作卷或私有控制卷。
4. 确认实例消失后记录目标镜像、旧镜像历史，并保留恢复租约直到调用方确认。请求或回执不明确时不会解锁新执行者。
5. 维护阶段结束状态是 `registered`，没有实例。下一轮真实获授权 Run 才初始化新镜像、挂载原盘；不借用虚构模型 Run 给维护程序取得执行权。

已有目标的完成状态可以幂等回读；失联后仍处于 starting/recovering 的状态须等待当前持有者或按过期恢复契约处理，不能将看到目标镜像字段等同于实例已经就绪。

维护操作不进入模型工具目录，也不作为公网 API 提供。新增的内部镜像检查需要原节点私钥并在解析请求体之前鉴权；它不能选择其他节点、卷或读取用户文件。真正升级还须满足有效恢复租约、启用范围、账号、租户成员关系及未归档个人会话。账号撤销后只保留既有停止/恢复清理能力。

## 迟到实例与历史

0052 仅为 `assistant_computers` 增加非空 JSON `retired_images`，旧记录默认空数组。旧镜像记录只允许恢复流程辨认并停止属于原用户、原电脑、原卷的迟到实例。普通命令、文件操作和启动仍只接受当前镜像，不能借历史镜像扩大执行范围。

Docker 创建请求若丢失回执，可能在升级后才出现旧容器。新启动会拒绝这种镜像不符的实例，保留租约待恢复；恢复可以依据历史清理它，之后重新初始化当前镜像。未记录的镜像、其他用户或其他盘一律拒绝删除。

镜像历史非空时，0052→0051 降级明确拒绝，保留恢复依据。镜像回退应继续使用理解历史的控制服务和 0052，通过同样的维护流程切回已验证固定镜像；不能用删除历史或恢复旧数据库来代替回退。生产完整回退实测尚待后续真实桌面镜像阶段完成。
