# 调用轨迹思考归组修复

此前“思考收进助手”的实现仍在，但后续上下文整合为 provider 流增加了工具边界分段：调用轨迹把分段编号加入全部思考 ID，并要求思考与助手位于同一段。因此工具回调插入时，同一 SDK 思考块会被切碎；工具之前的思考又无法归入工具之后的助手消息。对话过程区已有的稳定 SDK 块修复没有同步到调用轨迹。

现在两处共用 `isStableReasoningBlockId`：Run 内唯一的 SDK 思考块跨工具回调保持相同身份，未标识或复用 ID 的 provider 流继续按真实边界区分。调用轨迹按事件顺序将思考归入下一条助手消息，不同思考块以段落分隔，避免用时钟容差错误选中上一条回复；时间轴覆盖被归入的思考和答复事件。工具行及轮次边界保留，没有后续答复的思考继续可见。
