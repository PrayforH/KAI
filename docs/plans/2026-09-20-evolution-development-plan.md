# 智能体持续改进：开发设计与执行计划

基线：4a43a400，分支 `auto/agent-evolution`。独立工作树开发，不带入其他任务未提交修改。验证目标：173（现有 SSH 配置）；凭据不入库。

## 交付边界

把 9 月 19 日方案落实为可运行的持续改进控制面：质量事实、可信评测、问题证据、受限候选、基线对照、人工审核、受控发布、经验与观察。复用现有 Studio、EvalController、DeploymentService 与数据库。后续 GEPA/RL 与真实业务收益研究不作为生产依赖。没有专家金标时只证明工程行为，真实业务收益必须保持“未验证”。

## 实现顺序与验收

- [x] D1 质量事实：trace 可空；未知成本显式 unknown；终态重放幂等；人工反馈不依赖遥测；不向外部导出无 trace/未知分值。
- [x] D2 评测：结构化失败、成本/Token/工具调用预算与路径断言；CLI 重采样隔离；版本化 split/family；对照结果与缺证据判定。
- [x] D3 持久进化控制面：tenant/owner 隔离、版本 CAS、冻结任务与预算、证据来源、白名单 patch 与 diff、取消和停止。
- [x] D4 独立实验：候选隔离草稿/版本，复用真实 EvalRun；持久关联基线和候选；不可由客户端提交分数获得批准；验证冻结输入与 hash。
- [x] D5 审核和发布：审核绑定候选及报告 hash；模型服务凭据不能审核；拒绝、过期与回归门禁；复用发布、灰度及回滚服务。
- [x] D6 经验与回流：独立于个人记忆的有来源经验；候选/审核/撤销、失败诊断与观察记录；不能偷偷提升共享范围。
- [x] D7 Studio 界面：持续改进列表、候选 diff、实验和审核操作，复用 BFF 与权限。
- [x] D8 测试：质量、评测、并发 CAS、越权、证据缺失、审批绑定、候选隔离、持久化以及端到端闭环；前端构建。
- [x] D9 173 验证：先只读核对部署与版本；独立端口/数据库验证迁移、API、worker 与 UI，保留现有服务；留存脱敏结果、部署清单与回退命令。

## 数据与并发

新增 evolution records 存储聚合对象，主键 tenant + job_id，owner 进入每次访问过滤；数据库 revision CAS，状态/数据在一次事务中更新。实验执行继续走既有耐久队列，稳定 idempotency key 绑定 job/candidate/trial，重复 HTTP/worker 调度不得重复运行。对已存在的任务重试恢复，严禁伪造评测结果。对象保留完整来源与状态历史；不从用户记忆隐式导入团队经验。

候选只允许业务 Prompt 字段和已存在 Skill 的 instructions 修改。冻结完整 DraftSpec、允许修改目标、基线发布版本、预算与数据集版本；禁止改模型、工具/权限、评测用例。修改后必须重新编译，正式发布前重新检查候选、数据集与运行条件未变化。优化器只提出 patch；是否接受由固定校验与人工审核决定。

## 发布和风险处理

本轮在 173 使用隔离验证部署，避免覆盖其他运行任务。验证环境允许对测试智能体执行审核发布和回滚，但不代表授权任何业务智能体自动更新。真实金标、长期业务观察、第三方优化算法收益必须单独列为尚待验证项，不能以 fake runtime 的成功率代替。每个开发包完成后更新本计划与验证记录。

## 本轮执行结果（2026-09-20）

D1–D9 已按上述第一阶段边界完成。173 独立站点为 http://172.20.109.173:3302 ，API 为 8802。原 3301/8800 服务保留。详细证据见同目录 `2026-09-20-evolution-173-validation.md`。

实际实现为 `src/harness/evolution` 聚合服务、PostgreSQL 0035 迁移、Studio 持续改进工作区，以及质量/评测/发布服务的增量扩展。候选不修改来源草稿；通过内部 preview 运行基线和候选，审核后发布正式版本。运行控制台可以明确选择该审核版本，避免误用来源草稿的旧版本。

验收：后端全量 1717 passed / 6 skipped；前端 715 passed / 1 skipped；Next 构建、Ruff、新增控制面专项类型检查通过。全仓类型检查仍存在历史债务，不能标记为全绿。真实模型固定输出对照为 0/3 → 3/3、零回归；完成审核、发布、发布后观察、90/10 环境路由、环境快照回滚和个人版本回滚。该结果仅验证工程机制。

### 对原设计的明确收敛

1. 本轮保留外部/人工候选提案入口，没有启用 GEPA、DSPy 或 RL 自动优化器；优化器后续只获得 patch 提案权。
2. 预算是候选数、用例数、重采样次数、超时以及成本调度预留。保留项目已有“不设置费用/Token 执行额度”的产品约束；实际费用缺失阻断审批，已观察超额阻断后续调度。预留额度不是供应商账单硬上限。
3. split/family 已进入数据模型，本轮只允许 validation 数据集建立任务；独立 holdout 服务、近重复去污染与专家金标流程尚未交付。
4. 经验可记录、审核和撤销，保留来源及适用条件；没有自动注入个人记忆、团队知识或 Prompt。
5. 任务/实验意图持久化并由 reaper 恢复；发布遇到中断可在审批有效期内重试。审批过期后的 releasing 状态恢复需人工处理，不能宣称所有故障均自动恢复。
6. 已发布个人版本与环境部署指针独立。个人回滚不会自动撤销环境发布；环境需回滚到已验证快照。发布后来源草稿保持冻结，下一轮需在 Builder 显式采用新版本内容并发布新基线。

### 下一阶段建议（未在本轮启用）

- P1：选定真实业务，建立专家金标、互斥 train/validation/holdout 与冻结回归集，补充泄漏/重复检测。
- P2：为 proposer 定义适配接口，先接一种可替换的优化器，对照人工 patch；优化器不得读 holdout、改评分器、扩权限或调用发布接口。
- P3：审批后基线采用流程、发布事务恢复、自动质量事实补采、重启中的长任务恢复压测。
- P4：有足够发布后业务样本再判断收益；通过统计门槛后讨论扩大灰度和经验共享。
