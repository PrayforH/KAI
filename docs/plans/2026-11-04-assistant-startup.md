# 主助理首屏加载

用户要求修复79主助理加载慢；IM状态晚于聊天首屏加载，电脑仅在点击打开后连接。基线为最新电脑分支ff383602，隔离工作树fix/local-computer-link-20261104；不覆盖共享工作区。

现场：最近10项历史约303066字节、24条消息，隔离只读生产组合根测得1000/1326/1673ms。收到的子助理消息投影读取了整个候选窗口的事件（1327ms），虽其中多数未进入当前页；浏览器还在启动时回放23个旧子Run的完整事件，导致历史重复刷新。BFF压缩JSON删除ETag，主会话每3秒同步因此不能使用304。

实现：先合并分页，再并发读取本页收到的结果；已有最终结果使用与历史一致的版本化snapshot。条件请求在正文投影前返回。压缩后保留弱ETag，API接受其语义校验。历史回执不再启动Run回放，只观察当前页面新发消息，刷新请求合并。过期子问题不重复读详情。IM在对应会话历史就绪后挂载；电脑按钮首屏不请求状态，桌面占用仅打开时读，原桌面组件继续按打开状态挂载。

验证：响应内容/分页/所有权、压缩304、旧回执零回放、电脑关闭零桌面连接、问答/授权投影回归、TypeScript/Ruff；对新构建镜像用相同只读现场数据测量。最初首屏切片仅更新79 API和Web；随后子Bot电脑授权更新API、Worker与Computer Control。CAS备份发布、健康检查及实页核对，保留聊天、电脑绑定、磁盘和通道配置。

## 用户最新收敛

状态发现接口实测13–22ms，RFB私有传输握手约1025–1041ms。消息就绪1秒后可以静默发现电脑入口，但不连接桌面；移除上次打开偏好导致的自动重连。IM也只在对应会话消息就绪后挂载。

先给编码协同启用`config.execution_environment=personal_computer`，复用本人当前选定的本地电脑与现有Computer租约。平台按能力字段判定，不按名称写死，不默认给所有Bot启用，不改变普通/项目任务的环境。不增加排队、优先级或工作目录重构；占用冲突沿用既有独占拒绝。验证普通子Bot无授权不会改走电脑，启用Bot可获取工具和本地命令结果，暂停/归档/撤销配置/跨用户与项目隔离仍拒绝。为同步授权判定，需要更新Worker与Computer Control的同一access模块；远端系统组件及其pin不变。

演示目标：主会话发给编码协同 → 子Bot在本地电脑只读执行 → 结果回主会话，不改业务文件或创建定时事项。

实际验收发现编码协同沿用旧职责会话，不能只识别新Bot的会话前缀。授权解析追加旧职责的持久归属：同租户/本人、活跃且无项目/托管任务的职责、明确关联到已启用电脑能力的Bot，再走同一生命周期和执行租约校验。保留原会话和历史，不通过新建替身线程解决；暂停、归档、撤销能力、跨用户或普通/项目任务不得得到本地电脑。
