# 11.26 VM操作耗时拆解与Jev Ultrafast借鉴计划（2026-11-05）

## 11.26.1 测量口径与结论

可以借鉴Jev的运行时设计，优先做浏览器专用的轻量执行循环，同时保留现有原生桌面工具处理操作系统和非DOM界面。本轮只记录分析与后续工作，不将这些候选方向写成已经实施。已上线部分是11.25的同一可见VM、Vercel原生接口、默认完整身份读取及GUI延后工作区扫描。

当前样本来自79真实Run事件时间戳，起点为run.queued，终点为run.succeeded；工具区间为tool.request至配对tool.result。重叠工具取区间并集，不将并发等待相加冒充总耗时。两次测试不是同一任务的严格A/B：冷场景要打开浏览器并进入IANA，暖场景复用已打开的浏览器点击About。各只有一次，不能据此给出P50/P95、通用提速比例或成功率。

| 区间／事实 | 冷场景 | 暖场景 |
| --- | --- | --- |
| 完整请求（排队至结束） | 102.755秒 | 28.738秒 |
| 排队至运行开始 | 2.111秒 | 2.060秒 |
| 工具请求区间并集 | 27.012秒 | 13.391秒 |
| 上下文压缩区间 | 35.367秒 | 本次无此事件 |
| 扣除以上区间的其余耗时 | 38.266秒 | 13.286秒 |
| 工具调用／截图数 | 16次／4次 | 4次／0次 |
| 首个工具请求（相对排队） | 8.095秒 | 6.156秒 |
| 最终网页已由工具确认 | 62.618秒时 | 24.667秒时 |
| 实际结果 | Example Domain→IANA Example Domains | Example Domains→About us |

“其余耗时”包含模型预填充／推理、工具间调度、结果生成、传输和持久化，当前不能全部归因于模型推理。未单独测量浏览器绘制、首个用户可见文本token、纯SSH传输、CLI启动和D-Bus读取；日志中的reasoning.delta不是用户首段回复，不能当首token验收。

## 11.26.2 哪些地方值得优先优化

冷场景在62.618秒时已通过原生新快照读回目标页，62.665至98.032秒发生上下文压缩，额外占35.367秒。这是明确可见的长尾来源。应减少浏览器操作循环携带的整段聊天与重复快照，把可独立验证的进展及时发出；主会话的归档摘要和浏览器执行状态应分开设计，避免把压缩结束作为用户看到已确认结果的前提。涉及最终成功判断时仍须有独立结果验证，不能看到某个工具ok就提前宣称整项任务完成。

冷场景四次截图的工具返回时间合计约3.387秒；图像导致的模型视觉推理和后续回合成本不在这个数字里，因此既不能说截图影响只有3.4秒，也不能把102.8秒都归因于截图。打开一次浏览器用了多轮观察和坐标动作，后续可增加受控的“打开现有浏览器／激活窗口”能力，复用同一可见profile，减少启动阶段依赖视觉找图标；这是通用电脑能力，不是为某个业务写固定点击脚本。

| 暖场景工具 | 实测耗时 | 说明 |
| --- | --- | --- |
| 窗口枚举 | 2.037秒 | 含首次执行租约、控制与远端调用 |
| 完整IANA控件快照 | 3.568秒 | 173个引用，身份完整 |
| About语义点击 | 3.978秒 | 交付后不自动重试 |
| 目标页完整快照 | 3.809秒 | 231个引用，读回About us |

暖场景工具并集约占46.6%，工具区间之外约15.346秒。若其余路径完全不变，即使把工具耗时降到零，该样本仍约15.3秒；只优化浏览器执行器无法直接推出七秒完成。因此要同时减少整窗身份普查／连接开销，以及模型决策回合和上下文体积。这里是单次样本的条件分析，不是性能预测。

原生动作每次重建CLI与连接，Chromium引用还需完整窗口身份观察，这是3–5秒工具成本的候选来源，但目前没有内部span，不能认定其中哪个占比最高。8000毫秒是允许读取完成的上限，并非固定sleep；单纯缩回两秒会重现身份未证明／拒绝点击，不能作为提速办法，也不能去掉身份校验。

## 11.26.3 Jev哪些思路可以采用

已核对公开仓库检查点8251e272398011cdef648965204d1c20cd838333的README、性能说明及agent.py、browser.py、snapshot.js、model.py。可复用的是原子读取、受观察对象约束的动作空间和轻量循环。不能把接入CDP、换一个模型名或压缩截图等同于完整复刻。

| Jev做法 | KAI拟采用方式 | 必须保留的边界 |
| --- | --- | --- |
| 一次浏览器调用读取当前可见DOM与控件 | 增加浏览器专用原子snapshot，返回精简元素表与页面标识 | 仅当前VM可见浏览器；脚本由平台固定，模型不能提交任意JS |
| 持有真实节点身份，执行前校验页面／目标／上下文及遮挡 | 节点句柄绑定target、document、Run租约、桌面epoch和快照代次 | 导航、节点替换或接管后旧引用失效；不凭复用编号点击 |
| 一次模型请求同时选择动作和目标 | 先用现有模型的结构化输出联合产生op＋target，只允许本次状态中的可用组合 | 不生成任意选择器、坐标或代码；并行预测不等于并行执行写动作 |
| 只有填写动作才生成文字 | 试验小上下文文字助手，或同一结构化请求按需返回文本；比较额外一次调用的代价 | 文本是数据，先校验格式与字段约束；不把模型文本当代码执行 |
| 一条持续会话，动作与下一轮观察靠近执行 | VM内常驻受控broker，复用连接，动作后返回有界新状态 | 每个动作仍检查租约／控制权，接管必须排空；未知交付不重放 |
| 等待实际可用状态，减少整页变化导致的无效重试 | 等待目标出现、建议列表或导航结果；与动画无关的变化不强制重做决策 | 不能照搬演示中的50/200ms为所有网站固定等待 |
| 精简可见文本与近期动作 | 浏览器子执行器仅保留目标、必要授权约束、最新观察和有限近期动作 | 主助理聊天历史、任务／项目会话和执行上下文保持各自边界 |

Jev样例默认创建一个同profile的后台标签，并用焦点模拟保持渲染；这部分不直接照搬。KAI要求右侧看到同一页面，应优先附着现有可见标签，若确需新标签则明确激活并绑定该target；不能在后台完成后把另一页面展示成操作现场。浏览器专用通道与AT-SPI并存，原生系统对话框、桌面应用或不支持DOM的内容继续走原生／视觉能力。

Jev的动作／目标选择依赖TypeSafe服务，文字生成还使用独立模型。这些模型能力不能由MIT客户端源码自动复制；先用当前KAI已配置模型做结构化决策原型，单独测决策时延及准确率，暂不新增外部密钥、付费模型或自动迁移主模型。仓库标MIT，若后续复用源码应保留原版权和许可。

性能对照须统一口径：Jev的7.073秒从首次预测开始、到接受DONE结束，排除浏览器建立、初次导航／首次观察及独立后验验证；匹配比较只覆盖同一任务和profile的三对运行。KAI上述102.755／28.738秒包括排队、运行准备和结果结束，不能直接作为“慢几倍”的公平比较。后续同时报告用户端到端口径与对齐后的执行循环口径，且无论计时是否包含验证，都必须保留独立验收。

## 11.26.4 后续工作包与验证标准

| 顺序／工作包 | 交付物 | 完成标准 |
| --- | --- | --- |
| P0 可测量与短上下文 | 补充队列、电脑取得、模型TTFT／推理、SSH、CLI、D-Bus／DOM、动作、观察和压缩span；隔离浏览器执行上下文 | 给出完整耗时对账；可解释首段与长尾；不把内部编号展示给用户 |
| P1 同一可见Chrome的DOM原型 | 私有broker附着当前target；固定原子snapshot、基于节点身份的click/type/select和单次动作回执 | 保持原profile与右侧同页；接管后旧动作拒绝；不开放通用调试／storage接口 |
| P2 常驻连接与合并观察 | 比较agent-browser私有连接、Jev式运行时与现有原生路径；动作返回回执与下一可用状态 | 减少CLI／SSH／浏览器协议往返；动作已执行但后验观察失败时仍保留执行记录，不重放输入 |
| P3 一次决策与小上下文策略 | 联合op/target结构化选择；填值按需生成；低推理动作策略与现有模型对照 | 不写死网站或业务流程；较少回合仍独立验证成功，复杂规划能力不被全局降级 |
| P4 对照采样与渐进启用 | 相同页面、目标、模型、profile、网络与起止点做交替对照；每组至少20次，失败全部保留 | 报告成功率、P50/P95、工具与模型时延、协议调用、token、截图及重试；通过后再按能力启用 |

测试集至少覆盖普通导航、表单／下拉、动态节点替换与遮挡、人工接管／迟到动作、会话恢复与网络中断；iframe、Shadow DOM、Canvas、文件上传、新标签和原生弹窗单列能力，不由通用HTML成功推导支持。只用合成数据验证，不读取真实Grok Vault，不继续已暂停的凭证执行取用。

平台继续只管理生命周期、权限、执行租约和消息投递；浏览器执行器是可复用能力，不增加天气／禅道／编码的固定业务分支，也不改变普通任务和项目任务交互。先完成P0与P1的证据，再决定TypeSafe替代、常驻服务及后续SLO；本记录没有承诺七秒，也没有启动额外模型测试、部署或长时间后台任务。
