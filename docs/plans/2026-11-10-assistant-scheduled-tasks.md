# 助理定时任务：对齐小树 2.0 原型的设计计划

2026-11-10。对象：`/assistant` 的定时任务（原型称「任务」）。依据两处事实：原型
`小树2.0_完整版.html` 的任务面板/编辑弹窗/执行记录，与 116 当前实现
（`bot-side-panel.tsx`、`bot-duties-dialog.tsx`、`duty-schedule-control.tsx`）。

## 1. 目标

让助理的定时任务在**能做什么**上和原型一致，而不是逐像素复刻：

1. 用「重复 + 时间 + 有效期」表达周期，覆盖单次/每天/每周/每月/每年。
2. 助理右侧有「任务」列表，可暂停、编辑、删除，能查看每次执行记录。
3. 推送渠道（微信/飞书）按任务选择——依赖后端能力，排在最后。

助理工作台不在本计划范围。

## 2. 原型行为

- 右侧栏三个 tab：任务 / 电脑 / 资料。任务 tab 顶部「定时任务」+ 数量，下面是任务卡片。
- 卡片菜单：编辑、删除。编辑弹窗字段：任务名称（≤40）、任务要求（≤200）、
  执行周期三格（重复：单次/每天/每周/每双周/每月/每年；时间：时、分两列；
  有效期：长期有效或起止日期）、消息推送（微信/飞书开关）。
- 执行记录是任务 tab 的**内页**（不是弹窗）：返回、任务名、状态筛选、类型筛选、
  周期摘要、记录列表、总数与分页。
- 助理回复的来源后面带「定时任务」标签。

## 3. 现状（116）

- 侧栏只有「动态 / 资料库」两个 tab；动态里有职责列表（标题、状态、启停开关、折叠的执行记录）。
- 周期编辑在「Bot 资料 → 职责」里，是一个「执行方式」下拉：
  按需 / 每 60/360/1440 分钟 / 指定时间一次 / 每天 / 每周 / 会议前提醒 / cron。
- 有效期只能通过聊天交办时的 `endsAt` 设定，界面上看不到也改不了。
- 执行记录是每项职责下的 `<details>`，无筛选、无分页。
- 没有按任务选择推送渠道；微信/飞书连接是账号级。
- 助理消息没有「定时任务」来源标签。

## 4. 差距矩阵

| 能力 | 原型 | 116 现状 | 后端支持 | 结论 |
| --- | --- | --- | --- | --- |
| 周期表达 | 单次/每天/每周/每双周/每月/每年 | 分钟间隔、一次、每天、每周、会议、cron | once/every/cron + 时区 | 前端补每月/每年；每双周需后端锚点 |
| 时间选择 | 时/分两列浮层 | `<input type=time>` | — | 保留原生控件即可，不是差距 |
| 有效期 | 长期有效 / 起止日期 | 仅交办时写入 ends_at | `ends_at` 字段已有 | P0 用 GET+PUT objective 带上 |
| 任务列表 | 任务 tab + 卡片 + 菜单 | 动态 tab 的职责行 | `GET /primary/duties`、`/objectives` | 前端重排 |
| 新建任务 | 列表内新建 | 只能聊天交办 | `POST /objectives`（需 agent 绑定） | P1 |
| 编辑名称/要求 | 弹窗两栏 | 无 | `PUT /objectives/{id}` | P1 |
| 删除 | 删除并停止执行 | 只有停止/完成动作 | `POST actions: stop` | P1 用停止实现，不硬删 |
| 执行记录 | 内页 + 筛选 + 分页 | 折叠列表，最多 100 条 | `GET /executions` 无筛选/分页 | P2 客户端筛选，超出再加参数 |
| 推送渠道 | 微信/飞书开关 | 无 | 无 per-objective 渠道 | P3 后端新增 |
| 来源标签 | 回复后标「定时任务」 | 无 | 执行带 `triggerKey=schedule:*` | P2 前端标记 |

## 5. 设计

### 5.1 规则到存储的映射

| 界面 | 存储 |
| --- | --- |
| 单次 + 日期时间 | `{kind:"once", at:"<ISO>", timezone}` |
| 每天 09:00 | `{kind:"cron", expression:"0 9 * * *"}` |
| 每周五 09:00 | `{kind:"cron", expression:"0 9 * * 5"}` |
| 每月 15 日 09:00 | `{kind:"cron", expression:"0 9 15 * *"}` |
| 每年 3 月 1 日 09:00 | `{kind:"cron", expression:"0 9 1 3 *"}` |
| 有效期截止 12-31 | `ends_at = 2026-12-31T23:59:59+08:00`（浏览器时区） |
| 长期有效 | `ends_at = null` |

`automation-schedule.ts` 的 `buildCron` / `readCronFrequency` 扩展
`monthly`、`yearly`（读出时必须能原样往返，读不出就保持「自定义 cron」）。
每月 31 日、2 月 29 日在不存在的月份自然跳过，界面文案要说明。

### 5.2 交互

- 右侧栏 tab 改为：任务 / 电脑 / 资料。「任务」= 现有职责列表 + 周期摘要 + 有效期 + 下次执行。
- 「编辑」打开与原型同构的弹窗：名称、任务要求、重复/时间/有效期；高级区折叠保留
  每 N 分钟、会议前提醒、cron 时区。
- 「执行记录」作为任务 tab 的内页：返回、状态筛选、类型筛选（定时/手动）、记录与分页。
- 「删除」= 停止职责（`stop`），文案说明保留记录不可恢复运行；不做硬删。

### 5.3 有效期与 CAS

`PATCH /objectives/{id}/schedule` 只带 schedule，改不了 `ends_at`。P0 的保存走：

1. `GET /objectives/{id}` 取完整 brief；
2. 合并新 schedule 与 `endsAt`；
3. `PUT /objectives/{id}`，带 `expectedRevision`。

并发编辑返回 409，界面提示刷新，不自动重试。

## 6. 分期

**P0 周期与有效期（纯前端，现有接口）**
- `automation-schedule.ts`：`buildCron`/`readCronFrequency`/`scheduleSummary` 增加每月/每年。
- `duty-schedule-control.tsx`：重复 / 时间 / 有效期三格；高级区保留原有能力；保存改用 PUT。
- 职责行显示周期摘要、有效期、下次执行。
- 验收：五种重复各保存一次并在刷新后原样读回；改有效期后 `nextCheckAt` 同步变化；
  并发修改提示刷新；不产生新的执行。

**P1 任务面板与编辑弹窗**
- 侧栏新增「任务」tab；任务卡片、编辑弹窗（名称/要求/周期）、暂停/恢复、删除（停止）。
- 新建任务：任务 tab 内「新建」，沿用当前 Bot 绑定的 agent 版本；没有绑定则引导先开聊。
- 验收：新建→出现在列表→刷新仍在；编辑名称/要求生效；删除后列表移除且不再执行。

**P2 执行记录内页与来源标签**
- 执行记录内页：状态/类型筛选、分页（先客户端，单任务超过 100 条再给 `GET /executions` 加分页参数）。
- 助理消息按 `triggerKey` 标「定时任务」。
- 验收：筛选结果与总数一致；翻页不丢状态；超量时提示只显示前 100 条（后端分页落地前）。

**P3 协议扩展（后端 + 前端）**
- 每双周：`ObjectiveSchedule` 增加锚点（如 `anchorAt`），`Timing` 支持带锚点的双周 cron；
  没有锚点时界面不提供该选项，避免从保存时刻起漂移。
- 推送渠道：objective 增加 `deliveryChannels: ["wechat","feishu"]`；worker 按渠道发送，
  `GET /primary/duties` 回传；账号未连接时开关禁用并说明。
- 验收：以真实账号各发一次，连接状态与发送结果可查。

## 7. 风险

- PUT 覆盖整个 brief：必须用最新 `GET` 结果合并，CAS 失败只提示刷新。
- 时区：界面时间按浏览器时区输入，存储显式带 `timezone`（默认 `Asia/Shanghai`），
  不做隐式转换。
- 每月/每年在缺日月份跳过是 cron 语义，不是 bug；文案注明。
- 每双周在后端锚点落地前不提供，避免「看起来对、实际漂移」。

## 8. 发布

- P0/P1/P2 只动 web：116 按现有 bundle 替换流程发布；79 待凭据后同样发布 web。
- P3 动 API/Worker：116 与 79 都要重建 api/worker 镜像，先备份私有 Compose 与业务库。
