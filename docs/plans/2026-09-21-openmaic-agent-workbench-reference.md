# OpenMAIC 对智能体工作区的借鉴方案

日期：2026-09-21。研究对象：[THU-MAIC/OpenMAIC](https://github.com/THU-MAIC/OpenMAIC)，检视提交 `ec20ba345f47911981eaf59b9e83aa91097a8a37`。依据 README 与工作台、编辑、会话恢复源码；未部署或完成其浏览器视觉体验。本文件为增量设计，不表示相关能力已开发或部署到 173。

## 结论与三个项目的分工

OpenMAIC 值得优先借鉴的是“围绕成果开展交互”的工作台。它把会话、可编辑成果、材料和执行过程连在一起，对本项目 Playground 的帮助比课堂人物形象、语音或动画更直接。

| 参考项目 | 在本项目中指导的部分 |
| --- | --- |
| Agenta | 单智能体配置试跑、成对评测、运行诊断与版本验收 |
| AgentTeams | 多智能体分工、任务交接、交付验收与人工介入 |
| OpenMAIC | 面向成果的工作台、局部修改、过程卡片、结构化追问与会话恢复 |

它们共同服务同一条链：真实任务得到成果 → 用户反馈定位问题 → 形成带来源的评测样本 → 验证智能体改进 → 发布新版本 → 用真实任务观察效果。这个闭环是本项目的设计建议，不能从 OpenMAIC 的课堂互动直接推导出它已经实现通用智能体自进化。

## 优先吸收的六项设计

### 1. 会话与成果面板独立

OpenMAIC 的 WorkspaceShell 把导航、会话、课堂分为独立面板；会话和课程分别写入 URL，可折叠、调整宽度，课程有页签。切换课程不应卸载会话或丢失输入；会话与课程也不是简单的一对一关系。[工作台源码](https://github.com/THU-MAIC/OpenMAIC/blob/ec20ba345f47911981eaf59b9e83aa91097a8a37/components/workbench/workspace/WorkspaceShell.tsx)

本项目已有构建对话、资产/代码、效果测试分区，应该升级其成果区域：报告、表格、结构化 JSON、图表先拥有独立预览页签；下载作为同一成果的操作之一。当前 agent-build-assets 与 agent-preview 中试跑文件主要呈现为下载链接，因此增量重点是可阅读的成果面板与稳定的选中状态。

推荐布局：顶部显示智能体、草稿修订与运行版本；左侧为用例、材料和历史运行；中央为当前成果；右侧为对话与修改建议。运行证据按需在抽屉展开。窄屏改为“成果/对话”切换，并保存各自状态。配置编辑继续保留独立入口，四个生命周期环节不再各自复制一套聊天窗口。

### 2. 选中对象，再提出修改

OpenMAIC 的元素引用包含课程、场景、元素 ID、类型、可读标签与有限的文本快照；输入框将它们展示为引用标签。[元素引用](https://github.com/THU-MAIC/OpenMAIC/blob/ec20ba345f47911981eaf59b9e83aa91097a8a37/lib/workbench/element-refs.ts)

本项目建议支持选择报告段落、表格行、失败用例、Prompt 段落或某个工具事件，然后提出“补出处”“修正这两行”“只修改这条规则”。引用建议保存 `artifactId / artifactRevision / locator / snapshotHash / runId`；服务端验证访问权限、修订和定位。对象已被修改时提示重新选择，不能仅依赖前端文本快照猜测写入位置。

明确区分两类动作：修改本次交付物，或改进智能体后重跑。前者不更改智能体默认版本；后者生成待评测候选。现有草稿修改预览与 expectedRevision 校验继续复用，不再新建一套配置差异系统。

### 3. 结构化成果与受限编辑

OpenMAIC 按不同 Scene 类型注册编辑界面，针对元素和画布校验补丁，禁止通过普通 patch 偷换元素身份或类型。这种做法适合迁移为按成果类型注册的渲染器与编辑器。[编辑器注册](https://github.com/THU-MAIC/OpenMAIC/blob/ec20ba345f47911981eaf59b9e83aa91097a8a37/lib/edit/scene-editor-registry.ts)、[补丁校验](https://github.com/THU-MAIC/OpenMAIC/blob/ec20ba345f47911981eaf59b9e83aa91097a8a37/lib/server/agent-runtime/course-edit/apply.ts)

第一阶段仅支持 Markdown 报告、表格和 JSON。成果具有稳定 ID、类型、修订、来源 Run 与生成它的智能体版本；修改形成新修订并可查看差异。预览先使用受控渲染器，交互式 HTML 后置并在隔离环境运行。无需引入整套课堂 DSL、课件编辑器或教学专用动作。

### 4. 让执行过程可读、可操作

OpenMAIC 将连续工具调用聚合成一组，执行中展开，结束后延迟收起，并尊重用户的手动展开状态。每次完整问答产出的课程卡片出现在对应回答末尾，不是每个模型轮次都重复显示。[工具分组](https://github.com/THU-MAIC/OpenMAIC/blob/ec20ba345f47911981eaf59b9e83aa91097a8a37/components/workbench/chat/tool-group.tsx)、[事件视图状态](https://github.com/THU-MAIC/OpenMAIC/blob/ec20ba345f47911981eaf59b9e83aa91097a8a37/lib/workbench/session-store.ts)

本项目建议在 Playground 展示材料读取、执行计划、工具调用、成果更新、等待用户和结束摘要等卡片。工具参数和原始 Trace 保留在详情中。错误和待处理审批不能被自动折叠隐藏；只有后端提供计划与完成事件时才显示确定的进度，不能将加载动画包装成虚构百分比。

### 5. 结构化追问及明确的恢复状态

OpenMAIC 的 ask_user 输出完整问题和选项，结束当前执行，用户下一条消息推动后续运行。前端问题卡区分待回答与历史已回答。[追问工具](https://github.com/THU-MAIC/OpenMAIC/blob/ec20ba345f47911981eaf59b9e83aa91097a8a37/lib/server/agent-runtime/ask-user.ts)

可借鉴为任务缺少必要信息时的选项卡和输入表单。但源码中的回答关联采用后续普通用户消息推导，不足以直接承担本项目高影响审批。我们的问题必须保存 questionId、runId、修订和回答记录；工具审批与发布审核继续使用各自独立接口。恢复历史消息时不重新激活已处理按钮，超时也不表示同意。

OpenMAIC 的恢复策略保存会话记录，并修复中断的工具调用；其源码明确指出工具可能至少执行一次，因此需要幂等。这不能等同于通用运行时都可以无损续跑。[恢复语义](https://github.com/THU-MAIC/OpenMAIC/blob/ec20ba345f47911981eaf59b9e83aa91097a8a37/lib/server/agent-runtime/resume.ts)

本项目先统一显示“可重连查看”“可继续会话”“需重新执行”等实际能力，复用已有 Run/Session/事件序号；外部副作用操作必须有幂等键或人工核对，旧 Worker 在租约失效后不能继续提交变更。

### 6. 多角色围绕同一对象交互

OpenMAIC 的课堂 Director 使用角色调用、当前场景证据与交还用户控制等工具组织讨论，同时限制角色轮次与动作数量。[Director 实现](https://github.com/THU-MAIC/OpenMAIC/blob/ec20ba345f47911981eaf59b9e83aa91097a8a37/lib/chat/pi/director-loop.ts)

可迁移为“分析者出结论、核验者查证据、人类作决定”的成果评审。每条意见绑定同一产物修订和具体位置。课堂中的角色发言顺序不直接替代 AgentTeams 式任务依赖、业务验收和权限控制；角色之间一致赞同也不能当作客观评测通过。

## 建议调整的开发顺序

| 优先级 | 增量开发 | 验收证据 |
| --- | --- | --- |
| P0 | 成果预览页签；运行与修订标识；工具分组与状态摘要 | 切换成果不丢输入；重复回放不重复生成卡片；错误可见 |
| P1 | 选中成果内容发起局部修改；新修订、差异和撤销；结构化问题卡 | 旧修订拒绝覆盖；权限检查；已回答问题不可重复提交 |
| P2 | 协作评审；“转为评测样本”入口；关联候选实验 | 反馈能追溯到产物、位置、Run、Agent 版本；样本先审核再进入数据集 |

优先级与 AgentTeams 方案协调：P0/P1 可先改善单智能体体验，P2 再接入项目级协作，避免同时引入多个新控制面。

## 建议人工验收场景

用一个“读取两份材料，输出有出处的对比报告”任务：在工作台查看成果，选中一段指出出处不充分，确认只修改本次报告；对照修订差异接受修改；随后将这类问题转为评测样本并创建智能体改进实验。刷新页面后材料、成果、对话与问题卡状态一致；历史 Run 和原报告仍可查看；未发布的候选不改变当前默认版本。
