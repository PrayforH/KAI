# 助理群聊（Grok Bot 编码协同）总览

日期：2026-11-11 · 分支：`auto/bot-runtime-alignment-20261109`
入口：https://172.20.105.79:3543/assistant → 右上角「群聊」，或 `/assistant/groups`

## 目标

在助理域新增「带花名册的共享会话/频道」：一个群有名称、创建者、主助理和若干
专职子助理；@ 谁谁在本群回复，未 @ 时由接话人（默认主助理）直接回复；群消息
与 1:1、其它群隔离。不复用 `/v1/groups` 用户 ACL、Team Space、侧栏 ProjectGroup
或 1:1 的子助理分派逻辑。

## 数据模型

- `assistant_groups`：群名称、owner、`payload.primaryPresent`、`payload.replyAs`、
  `payload.lastReadAt`。
- `assistant_group_members`：群内席位（creator 由服务层拼出，不落库；
  primary / specialist 落库），移出后保留 `status=removed`。
- `assistant_group_messages`：群时间线；回复先落占位行，再从 Run 事件补水；
  `client_message_id` 幂等。
- `assistant_group_reactions`：按群/消息/用户/emoji 存表情。

迁移：`0073_assistant_groups`、`0074_group_unread_reactions`。

## 应答与隔离

- 每个群成员一个专属线程：`assistant_group_<group_id>_primary` /
  `assistant_group_<group_id>_<specialist_id>`；线程前缀保证群消息不会进入
  1:1、任务列表或其它群。
- 解析 @ 时按 NFKC 规范化，成员名最长优先匹配，去掉 @ 后再投递给被点名者。
- 未 @：按 `replyAs` 选接话人；默认主助理。接话人/主助理已被移出时只写一条
  系统提示，不改派给其他成员。多个 @ 会分别唤醒各自线程。
- @ 非成员或已移出者：写一条系统提示，不投递、不报错。
- 时间线由 REST 合并各线程回复；刷新后从 Run 事件恢复同一答案。

## P0（79 必过）

1. 共享会话有名称与成员列表，可拉人/移出。
2. 建群默认含创建者与主助理；空/非法名称明确失败且不落脏数据。
3. 只能拉/移出自己的专职子助理；移出后不在名单、不能再发言或被 @。
4. 主助理被移出：未 @ 不改派，明确提示；其他成员仍可用。
5. 未 @：主助理在本群直接回复，子助理静默；刷新后仍在。
6. @：被 @ 子助理以自己身份回复；@ 主助理则主助理回复；未 @ 者静默；
   @ 非成员/已移出者明确提示。
7. 群消息不出现在无关 1:1 或其它群。

## P1

- 可配置「未 @ 接话人」（默认主助理；可改为群内子助理）。
- 接话人被移出后不自动改派，并给明确提示。
- 一次 @ 多人：被点名者都回复。
- 新成员能看到入群前历史（群时间线为共享视图）。

## P2

- 未读：群不在当前查看时列表显示数量；进入即清零；只计本人本群；无推送、
  通知中心或已读回执。
- 表情：固定 emoji（👍 ❤️ 😂 🎉 👀）可加减，刷新后仍在，只在本群；无表情
  商店/自定义；助理不跟表情。

## 明确的非目标

- 按消息内容自动判断该谁接（Jev/Auto 选人）。
- 群附件、回复某条等其它完善。
- 116 预发布：等 79 通过后按离线约束协同部署，不依赖外网拉包。
