对照结论

差异在「谁是联系人、群里谁开口、1:1 与群是否同一套决策」。不是再写一份 KAI 现状说明书。
  • KAI 助理域是企业工作台上的专属 /assistant 面：一个主助理加多名职责子助理（Specialist），各有 1:1 会话。跨助理协作在 1:1 里走「发送 / 回执」，由平台校验归属与权限，不再强制每轮分类路由。团队空间用来共享已发布 Agent 版本，不是群聊。群组能力按今晚群内口径要对标「主理」，但提交 f9c3872a 在 GitHub 上未找到，本页不把它写成已验证落地。
  • OpenMausBot 把每个 Bot 当成通讯录里的联系人：独立人格、模型、电脑和 1:1 线程。频道 / 房间是带可编花名册的共享 transcript，应答模式包括主责、全员、仅 @，以及 Auto（Jev / Clef / OpenRouter）给未 @ 消息选人。
  • Grok Bot 今晚在群内自述：群是带花名册的频道；没有 MausBot 那种 Jev 自动选人层；被 @ 的人应当回应；未 @ 时成员自己判断是否开口，有协调人时一般话由协调人接；1:1 与群分开。内部实现（存储、进程、路由代码）未在公开资料中找到，本文不猜测。

谁来回答

这是三方最需要并排看的决策差。KAI 的 1:1 职责分派、OpenMausBot 的房间 Auto、以及今晚锁定的 KAI 群「主理」，不是同一套机制。

情形KAI 1:1（当前分支）OpenMausBot 房间Grok Bot（今晚自述）KAI 群（今晚锁定，未复核代码）
未 @ 的一般话 主模型可自行处理、发送给子助理或提问；平台不再强制每轮 assistant_route_message 分类。服务端仍校验归属、权限、附件与投递幂等 视房间模式：主责、全员、仅 @，或 Auto。Auto 用决策模型（默认 Jev，也可 Clef / OpenRouter）在 1.5 秒内挑选；概率 ≥ 0.6 才独立点名，「多人」达阈值则全员；失败开放，回退主责 成员自己判断是否有必要开口；有协调人时一般话由协调人接 专职子助理必须静默；一般话由本群「未 @ 接话人」直接回，默认是主助理（主理，不是「仅 @ 才回」）
有 @ 可用 @ 把话直接交给对应子助理；结果可回到发起会话，带来源行 @ 与 @everyone 不走决策模型，被点名的 Bot 回答 被点名的人应当回应 被点名的成员以自己身份在本群直接承办；主助理不中转、不抢话；@ 主助理则主助理回；@ 非成员或已移出者必须明确提示
决策器与 1:1 的关系 历史上（2026-11-03 上午）曾用 assistant_route_message（dispatch / direct / clarify）并在 79 用真实浏览器验过；同日自主化改造删除了强制分类与工作流门控，现工具为 assistant_create_specialist 与 assistant_send_message 决策模型只服务房间 Auto 的未 @ 消息，不代替 Bot 自己的引擎干活 明确没有 MausBot 那种 Jev 自动选人层 群应答不得与 1:1 的历史路由工具或发送工具混成一套；Auto / Jev 列为下一期可选房间模式，失败回退接话人

KAI 已经在 79 验证过的，是主会话与子助理会话之间的发送、提问卡和回执，而不是房间级轮流发言。OpenMausBot 房间成员的回合是房间 transcript 上的根回合。不要把前者画成后者。

今晚群内锁定（KAI 群组口径）

以下不是仓库旧文档，而是 2026-11-11 当晚「AI产品研发组」锁定的产品口径。P0 / P1 / P2 只作一脚索引，不是本页主体。

  • 群是带花名册的共享会话；建群时创建者和主助理默认在群；只能拉 / 移出当前用户的专职子助理，不能拉其他真人。
  • 未 @：接话人（默认主助理）在本群直接回，其他专职子助理静默。不是「全员不回」。
  • 有 @：被点名者以自己身份直接承办，主助理不中转。移出接话人或主助理后，未 @ 不自动改派，并给明确提示。
  • 消息只出现在本群，刷新后还在，不泄漏到 1:1 或其他群。
  • Jev / Auto 下一期；不要和 1:1 的 assistant_route_message（或其后续发送工具）混用。
  • P0（今晚 79 通过线）对应验收 A–L；P1 为可配置接话人、一次 @ 多人、入群前历史；P2 为未读与表情。计划入口 https://172.20.105.79:3543/assistant（编码协同口述，本页未做现网探活）。
