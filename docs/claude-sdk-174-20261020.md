## 真实验收中发现并修复

### 项目与子智能体共享 MCP 被误判冲突

原实现按 Agent 快照归属拒绝同名 MCP，即使最终 HTTP/SSE 地址、请求头和凭据完全一致，也会在模型调用前报 `MCP server name conflicts across Lead/Sub Agents`。

`0fc7e03c` 允许相同的已解析远程连接共享，同名但不同地址、请求头或传输方式继续拒绝；SDK 进程内工具仍保持原归属约束。集成测试同时覆盖共享成功和三种冲突。

### 后台子智能体被首个 result 提前中断

新版 CLI 的 Agent 调用省略 `run_in_background` 时可以进入后台。旧适配器把首个 `ResultMessage` 当成整条 Run 的完成边界，导致两个子智能体出现 `missing_terminal_event`、主任务被标为成功但没有最终汇总，下一轮也可能无正文。

`59cefe68` 显式启用 `CLAUDE_CODE_EMIT_SESSION_STATE_EVENTS`，保留 MCP、Hook 和 Run 所有权，等待子任务生命周期完成、主智能体汇总以及 CLI 的 `idle`，只向 Worker 交付最终结果；旧传输回退到任务生命周期追踪。未完成的流关闭不能作为成功返回。`c4cce7a9` 补齐类型注解，行为与前一提交相同。
