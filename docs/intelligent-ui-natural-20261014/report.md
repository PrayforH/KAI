# 主对话 Intelligent UI 与附件的自然提问对照

2026-10-14。基准来自用户提供的《ChatGPT 上线【交互 UI】，让每个回答都能交互》及本地 GIF。这里比较附件呈现的行为，不把文章里的发布信息视为经过官方核实的事实。

## 结论

现有主对话已经能在部分自然请求中自动生成聊天内交互，但还不能稳定复现附件。当前 d1 接入负责真实工具记录的后置展示选型，不负责在回答开始前判断是否应加入计数器、模拟器、计算器或可操作清单。

174 的 shdata-model 组有 8 个独立自然请求，其中 4 个生成并发布 HTML 交互组件；Flash 对照 5 个请求，4 个没有呈现组件，1 个只发布了普通表格。四个 HTML 块全部是 `origin=model`，因此不能将这些成功归因于新增 d1 selector。

79 已验证 Tavily 图片检索和真实图片读取。页面默认通用助手版本 1.0.1 的三例首轮对话均未输出 Markdown 图片，也未发布丰富呈现组件。自驾与无人机研究实际调用了联网工具，工具返回了图片，最终回答没有采用。

## 提问方法和分组

每例独立新会话，使用主对话实际 AG-UI → Worker 路径。用户输入保留业务自然语言，没有附加 HTML、滑块、组件种类或 `harness-ui` 协议指令。

分账器与游戏本来就是附件中明确提出的业务工具需求，保留其自然说法。小票原图不可用，分账使用文本菜品数据，不计照片识别通过。退休账户示例改为普通“每月存钱”的问题，不用税法或账户资格作为前提。

第一组脚本的模型覆盖参数使用了错误的嵌套格式，实际执行 shdata-model；之后纠正为平铺 `forwardedProps.modelRoute`，独立重跑 Flash。所有模型归属均取 `harness.runtime.v1` 事件，不根据界面标签或请求中的预期模型推断。原始组保留，不用复测替换它。

174 Web 配置的默认智能体版本为 1.0.0；79 为 1.0.1。79 的 1.0.0 旧版没有声明 WebSearch/WebFetch，已从 SDK 初始化工具列表确认；这组仅作为旧会话对照。默认版 1.0.1 和已发布新版 1.0.3+platform.99dfe677 都有联网工具，分组记录，未修改默认版本。

穿搭继续输入“按这个示例安排：七月去佛罗伦萨，半正式婚礼，按女装；另外几天城市观光，只带随身行李。”返回了文字行李清单和逐日 Markdown 表格，没有图片、可勾选清单或呈现块。

自驾继续输入“按这个示例安排：西雅图进出，六月，两位朋友同行，偏户外徒步，每天驾驶尽量不超过三小时。”进行了联网搜索，返回文字行程和进一步选择问题，没有图片或呈现块。补充的是业务条件，没有要求任何 UI 类型。

两例沿用原 Thread，实际模型仍为 deepseek-flash；因此缺少 rich UI 不能全部归因于首轮信息不足。

## 真实浏览器操作

生成物的本地 Chrome 操作与主对话内联存在的验证分别记录。截图是本次实际生成文件的浏览器运行状态，没有重绘组件。

- 咖啡店模拟：样本量从 5 改为 16，重复次数 3000；理论标准差从 5.57 降到 3.11，n=16 的实际模拟标准差为 3.18。主对话里也已观察到内联 iframe，并实际将 5 改为 6，数值联动。未复现附件的相同消费分布和随堂题。
- 分账：默认 60 元、每人 12 元；取消第一人参与披萨后，此人 6 元，其余四人各 13.5 元，总额仍为 60 元。缺少附件中的金额编辑和 18% 小费，不计完整同效。
- 长期储蓄：每月 2000、20 年、期初本金 0；年化从 3 改为 0，余额变为 480,000，利息为 0。该例是计算行为测试。
- 游戏：内联 HTML 发布成功，三款为贪吃蛇、俄罗斯方块、打砖块；附件提到的乒乓不同，实际玩法未完成验收。

接受的呈现快照在实时流和历史读取中一致。这验证内容快照，不代表所有 HTML 的输入状态恢复均已在浏览器验收。

## 接近附件效果还需补的环节

1. 在主对话开始前，让 d1 判断是否值得加入交互，以及用户需要操作、探索或比较什么。结果作为呈现目标提供给主模型，业务提示词继续保持自然语言。
2. 主模型根据目标及可用数据选择现有组件或生成式 HTML，正文保持结论；单纯事实和不需要操作的回答可继续用文字。
3. 将已经返回的图片、描述和来源整理为可用展示数据，推动合适的回答实际使用图片。
4. 兼容本次真实观察到且可以无歧义转换的位置行数据，保留原有尺寸、标量与动作校验。失败时提供可观察的呈现诊断，避免原协议 JSON成为用户交付物。
5. 使用本轮自然问法重新验收：分开统计自动选型、实际渲染、控件结果与历史状态，不通过在用户输入中指定组件来提高数字。

以上是本轮比较得出的改进建议；未在本轮改写主对话策略或部署新版本。
