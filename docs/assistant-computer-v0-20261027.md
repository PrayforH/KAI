# Computer V0：注册、租约与工作盘实测

2026-10-27，北京时间。此迭代推进[持久 Computer 方案](plans/2026-10-27-assistant-dot-bot-computer.md)，尚未完成或开启线上用户电脑。79 现有飞书、微信、网页聊天继续使用原执行配置；生产数据库仍为 0050，未在本轮迁移。

后续进展：同日已实现 Manager、Docker 驱动与进程监督器，并通过 79 组件验收；见[Manager 迭代](assistant-computer-manager-20261027.md)。下文是前一检查点的范围与待办，真实 Worker / 桌面接入仍未完成。

## 已实现

- `computer/models.py`：电脑身份与状态、启动/执行/恢复租约。电脑按租户与用户唯一，实例引用与工作盘引用分开保存；任务结束不改变电脑身份或工作盘。
- `computer/registry.py`：数据库先保存稳定电脑及工作盘名称，再允许创建外部资源。注册并发通过 PostgreSQL 冲突处理收敛到同一行；全部租约变更串行锁住本人电脑行，不依赖进程内锁。配置变更要求显式迁移，不静默换盘或切换镜像。
- 租约使用数据库实时钟，在取得行锁后采样。到期不可续租或完成任务，也不能直接转交下一任务；必须进入恢复，完成 Provider 进程隔离后才能恢复可执行状态。旧 epoch、旧持有者、其他租户/用户及被篡改的 Run/Session token 均拒绝操作。
- 启动、执行和恢复共享一条互斥规则，历史租约保留。数据库额外约束每位用户只有一个 active holder、epoch 唯一、实例和工作盘引用唯一。首版采用每台电脑一个执行持有者；未来多个 Agent 的桌面与后台并发需另行扩展。
- 迁移 `0051` 仅新增 `assistant_computers`、`computer_execution_leases`，不修改原聊天、绑定、账号或 Run 表。
- OpenSandbox 客户端增加受控命名盘、带归属检查的重连、需要 Provider 确认的有效期续期。磁盘固定 `deleteOnSandboxTermination=false`；重连失败不删除原实例。生命周期创建错误不再回显响应正文，避免未来环境变量被异常日志带出。

注册表是内部控制服务，调用方须先解析并授权真实账号；它不是可接受任意用户 ID 的公开接口。数据库 fencing 也不等于物理进程已经停止，`finish_execution` 与 `complete_recovery` 的调用契约明确要求驱动先确认进程退出或旧实例消失。尚未有驱动和 Worker 集成来执行这项契约，因此不能据数据库测试宣称真实任务已隔离。

## 79 的真实工作盘试验

只创建随机命名的测试卷和两个短期测试实例，没有使用本人绑定、聊天记录或业务文件。使用 79 实际 `release-1.1.0` 服务及现有执行镜像，没有升级共享 OpenSandbox 服务。

1. 创建测试实例及命名盘，写入项目标记、用户目录工具、浏览器配置目录的测试 Preferences 文件。
2. 续期得到服务端有效期确认；关闭客户端，再由新客户端按电脑归属重连同一实际实例，读回所有文件。
3. 删除第一个实例并确认生命周期 API 返回 404。以 `createIfNotExists=false` 创建第二个实例，强制引用原有工作盘，避免把新空盘误当成恢复成功。
4. 第二个实例逐字节读回三项文件；HOME 为持久目录，用户目录工具继续可执行。两个实例 ID 不同，工作盘名称相同。
5. 删除两个测试实例，并通过 Docker 确认不存在；删除仅含本轮测试数据的专属卷。

证据：[工作盘实测](results/assistant-computer-v0-20261027/disk-probe-79.json)。这里只证明文件、用户目录工具与配置目录字节持久化，未验证真实浏览器登录、系统包恢复、桌面或 Agent Run。Docker 命名盘不会因为 API 填写 storage 容量就自动获得磁盘硬配额。

官方协议中，PVC 字段在 Docker 后端对应命名卷，支持关闭实例终止时删盘；生产实测进一步验证了当前部署确实保留数据。[OpenSandbox 生命周期协议](https://github.com/opensandbox-group/OpenSandbox/blob/main/specs/sandbox-lifecycle.yml)

- OpenSandbox 生命周期、execd 与会话回归结果见[测试结果](results/assistant-computer-v0-20261027/opensandbox-tests.txt)。新增测试覆盖磁盘保留语义、归属重连、不删除失败重连实例、续期拒绝假确认、非法实例路径与挂载路径。
- Ruff 通过；本轮 Computer、OpenSandbox 客户端及新增测试 Pyright 0 错误、0 警告。修正客户端原有的未知类型边界，未关闭严格检查。
- 隔离数据库完成全量空库升级至 0051、0051→0050→0051、原用户记录保留，以及新增表与 ORM 元数据比较无差异。[迁移结果](results/assistant-computer-v0-20261027/migration.json)

## 仍需完成的接入

1. Computer Manager 与 OpenSandbox 驱动：重连、有效期维护、持久 HOME/工作区初始化、失联恢复。请求创建结果不确定时按已保存电脑身份和 epoch 发现资源；不能仅凭超时重建，尤其要处理延迟到达的旧创建请求。
2. Provider 侧执行隔离：每个执行持有者独立进程组，取消/退出后确认清理；权限过期立即停止写入，恢复前确认旧执行无法再修改工作盘。数据库 token 不能单独约束已运行的远程进程。
3. Worker 的个人助理路由及工作区恢复策略：从本人真实 Session 推导电脑，避免把旧快照覆盖回长期工作盘。临时任务沿用旧沙箱路径。
4. 清理与治理：让 Run reaper 识别电脑持有的实例；空闲电脑由 Manager 管理，不由单轮任务结束销毁。工作盘删除保持独立生命周期。
5. 非 root 桌面镜像、真实浏览器 profile/keyring 验证、认证 HTTP/WebSocket 代理与人工接管互斥。
6. 接通后在 79 本人账号试点：两次真实助理任务复用同一电脑，文件/工具/profile 延续，Worker 重启与刷新不丢失，多端继续共用原对话；保留原绑定及聊天记录。完成这些前不宣称 Computer V0 已上线。
