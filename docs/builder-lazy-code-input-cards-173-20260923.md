## 原因与修改

代码视图不调用模型现场编写代码，而是从已保存草稿导出 DeepAgents 项目。原界面每次重新挂载都请求导出并传回全部文本文件，含大量 Skill 资源；实测 r14 有 262 个文件，响应约 8.7 MB。

- 增加项目源文件接口的 `metadataOnly` 和精确 `path` 查询，默认接口及 ZIP 下载行为保持兼容。目录返回路径、大小、摘要和延迟读取标志；选中文件后才请求正文。路径只与归档内条目精确匹配，不读取宿主路径。
- 中间栏仅展开目录时不请求正文；展开预览后只读取所选文件。旧文件请求晚到不会覆盖新选择，错误可单独重试。
- 同一草稿修订的目录和文件读请求合并，内存缓存 120 秒；刷新代码、数据修改、登录状态变化会失效缓存。取消一个视图的等待不会中断另一个视图共享的请求。超过 512 KiB 的文件不长期保留在客户端缓存。
- 服务端仍按草稿导出生成内容，不承诺首次请求零生成耗时。

截图中的回复使用了合法的 `version/title/questions` 结构，但没有包在 `harness-input` 代码块内，旧解析器不识别。公共消息解析器现兼容单独成行的完整裸 JSON 和普通 JSON 代码块，沿用 1–4 个问题、类型、选项、长度及唯一 ID 校验；拒绝未知顶层字段、歧义多卡片、未完成和非协议 JSON。

输入卡片仍只显示在最新、已完成且未被用户回复的助手消息下方的输入区域。答案由用户主动选择或填写后发送为普通用户消息，不执行 JSON 中的操作。历史消息显示可读问题，避免暴露协议 JSON。已有符合条件的消息重新渲染即可使用，无需修改数据库或重跑模型。
