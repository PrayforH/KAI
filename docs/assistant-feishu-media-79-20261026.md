## 实测发现并修复的问题

**图文漏收。** 最初只允许 text/image/file/audio，用户截图中的组合内容实际是 `post`，被类型过滤，未进入持久队列。已补齐 post 解析，并真实验证多图与配文。用户的原消息 `om_x100b62d8a590dca0c04135982a538dc` 通过官方消息读取接口取回，核对发送者与现有绑定后，按原 message_id 补入正常队列；不是伪造一次新的 WebSocket 投递。重复提交仍只存在一条入站记录。没有要求用户重发。

**刷新后的历史分页。** 网页初次只加载最近 10 轮；继续发送时，原实现会把未加载的早期轮次遗漏出可见路径。服务端现在用前一条历史消息的 Run ID、所属会话与文本后缀恢复缺少的前缀，保留编辑旧消息的正常分支语义。已测试追加、编辑和跨会话隔离。原始 Run 数据未删除；验收期间被遗漏的可见前缀通过正常 AG-UI 提交恢复，记录见 `history-recovery.json`，没有修改历史 Run 行。最后再次从只加载十轮的刷新页面续聊，完整路径为 28 轮。

最初自动选择 GLM 的图片试验曾失败（`run_05c5eff17cdd4cb2a3cde63b08bda54e`），原记录保留；最终图片验收均使用用户指定的 DeepSeek Flash。没有把失败试验记作通过。
