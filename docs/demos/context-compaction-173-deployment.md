### 展示与存储边界（晚间更新）

不新增完整模型请求的前后快照。新接口只读已有 `context.compacted` 和 `context.history.checkpoint` 事件，不复制历史、不额外调用模型、不写入审计正文。元数据与正文分开加载：打开面板读取最近 20 次压缩涉及的轮次，展开某一轮才读取正文。

“压缩前历史参考”是上一轮保存的有效历史，可能已经包含更早的摘要；“本轮结束历史”包含最新摘要及本轮新增提问、回答。两者都不包含完整系统提示词、工具定义或全部工具交互，因此不是完整模型请求的对比，也不冒充摘要模型的逐条输入。若一轮发生多次压缩，明确展示最后一次摘要及最终历史；运行时未提供检查点时只展示元数据，不推测正文。

按实际 JSON 体积粗略估算，如果完整请求平均 1 MB，每轮前后各存一份，100 轮约新增 200 MB/会话（尚未计入索引、备份和压缩）。此次展示没有这项新增存储。已有历史检查点仍有自身存储成本，并非零成本；本次没有修改历史保留期，也没有删除旧记录。

单个历史视图最多返回 200 条消息、合计 240,000 字符，每条最多 120,000 字符；发生截断时明确标注。读取仍受租户、会话所有者和运行所属会话校验约束，并对正文再次应用现有凭据脱敏规则。

自动压缩后由运行时继续使用摘要及近期消息，无需用户点击恢复。原有恢复点重建/切回能力保留在默认收起的“高级维护 · 故障恢复”中，仅当存在相关数据或操作能力时显示；它不能撤销模型压缩。面板使用灰白中性色，移除绿色强调。

## 结束闪烁与启动／停止闪回修正

正文原有实时、耐久、原生三条渲染路径，收尾会卸载 Markdown 后再挂载。改为单一 `AssistantResponse`，仅更换文本与状态，工具与思考仍独立展示。回归验证在流式、完成、历史接管以及启动下一轮时保留相同正文及段落 DOM。

历史同步统一为单个串行刷新循环，只有历史包含当前轮且可见回答未被截短时才接管；导入与释放实时所有权在同次提交内执行。旧请求失效后不再复用或污染最新缓存，被拒绝的历史不再发布旧运行状态，并保留已加载的较早轮次。停止后服务端尚未写完时继续显示当前回答并重试。启动时立即释放上一轮实时状态；停止后的迟到事件不能改动下一轮。运行归属取消“最后一条即可”的宽泛匹配，完成时间优先使用本轮耐久状态。

ResizeObserver 在绘制前同步校正跟随位置，避免处理区收起后先露出旧轮次、下一帧才回到底部。未增加逐字动画、淡入或滚动追赶。
