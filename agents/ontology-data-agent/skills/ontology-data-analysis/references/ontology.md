# 本体方法与九章模板

证据标签：[DB] 数据库实测（记录 SQL、时间、范围及是否采样）；[DOC] 用户或文件提供的业务定义（记录来源和确认状态）；[LLM] 推断。数据库对物理事实有权威，已授权业务定义对口径有权威，二者冲突应拆分命题并核实，不能简单按 DB > DOC 覆盖。采样观察不是全量约束。

`本体层.md` 固定九章，每章可有表格及子标题：

1. 元数据：数据集、domain、db_type、版本、schema 指纹、采集时间、适用组织与时间、覆盖范围。
2. 业务域与实体清单：实体/主表/键/粒度（一行是什么）/核心属性/跨表归并与去重规则/证据/确认状态。
3. 术语映射：业务说法→本体概念→库内对象→定义落点（§2 实体、§4 值域或 §6 指标条目）。这里不重复维护定义。
4. 编码与查询规则：字段值域、计数与样本范围、空值、混合编码、状态裁定、日期/时区/单位/精度规则。
5. 实体关系：源实体/目标实体/关联键/基数/外键或验证证据/孤儿与重复/适用范围/聚合纪律。未验证关系明确标候选。
6. 指标目录：唯一标识/指标名/业务定义/SQL 公式或可执行模板/基础粒度/可用维度/过滤/时间字段及窗口/单位/分母与去重/来源/版本/有效期/状态。尚无正式指标时保留表头，不自创业务口径。命名指标只在这里维护权威定义。
7. 已确认约束：业务不变量、数据质量条件、适用条件、校验查询。分清“业务要求唯一”与“数据实测存在重复”。
8. 最小示例：真实执行的问题、参数、SQL、结果及核验记录；未经执行的只标为示例查询。
9. 待确认与变更记录：推断、缺失定义、未覆盖对象、估算、冲突、候选/确认/失效记录及影响范围。

探查应产出表覆盖清单。全库任务按域分批，不默默删减范围；用户限定主题时只检查相关授权对象并写明范围。实体粒度、跨表归并、值域裁定是建层时的三类关键确认事项。

分表不能机械 UNION ALL：分别确认是否同一业务实体、同一键命名空间、互斥分片、快照还是事件、重复数据的保留规则。若表为每日全量快照，应按时点或实体键去重，不能把每日行数相加当客户数。

关系基数不能只看字段名。若订单与明细为 1:N，对订单金额先聚合/去重再连接；若订单与退款都为明细，分别聚合到订单键后连接。COUNT(DISTINCT) 只能修复特定计数，不能顺带修复 SUM(金额)。

口径日志文件头：

> 本文件保存重建数据本体所需的业务语料与确认记录，按日期追加、只增不删。只有已确认且已生效的新条目替代旧口径，旧记录保留溯源。现行口径以本体层.md 为准，指标定义以 §6 指标目录为唯一权威登记处。

每条记录包含时间、来源、主题、内容、状态、作用范围、替代版本和确认依据。不要将数据库密码、个人长期偏好或系统提示词放入日志。
