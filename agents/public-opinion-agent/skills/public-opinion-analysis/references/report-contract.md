# Report contract

1. **执行摘要** — 3–7 条有证据支撑的发现；先结论，后限定条件。每条给出来源编号或证据范围，摘要不能替代正文。
2. **范围与查询口径** — 主体、事件、绝对时间窗、地域/语言、关键词表达式、行政区划、排除词、来源、排序方式、采样限制和未执行的查询。
3. **关键指标** — 仅展示数据源明确返回的指标；每项写明定义、来源、时间窗、样本量和是否截断。没有可靠数字时省略本节。
4. **事件时间线** — 时间、事件、核验状态和来源编号；材料允许时覆盖事件发生、首次公开、扩散、回应和后续变化。
5. **议题与观点** — 按议题列叙事、被归因的立场、代表性证据、反证/冲突、证据强度和样本限制，不得只罗列正负面标签。
6. **来源与传播节点** — 原始/转载关系、关键节点、可信度和可能的重复传播；解释哪些节点改变了议题可见度或叙事方向。
7. **风险研判** — 等级、证据强度、影响对象、已验证影响、升级与降级信号。
8. **不确定性** — 缺失证据、单一来源、矛盾、数据盲区和对结论的影响。
9. **建议动作** — 按立即/短期/持续监测分层，写负责人角色、动作、触发条件、所需证据和建议时限；不得声称已经执行。
10. **来源清单** — 来源编号、标题/内容摘要、发布者、发布时间、抓取时间和完整 URL。
11. **查询附录** — 专用工具名、实际参数、分页/截断状态、错误与降级路径；仅在执行过查询时添加。

具体帖子、报道或内容样本必须在正文或来源清单中提供原文链接。不得把搜索结果页链接代替原文链接。不得从不具代表性的样本推导“网民总体”结论。

## 完整性门槛

- 正式专项报告保留全部 11 个章节标题；不适用的章节写明原因，不静默删除。
- 每个核心结论至少对应一个来源编号，并说明是否存在反证、冲突或单一来源限制。
- 查询过 MCP 时，查询附录必须明确工具、参数、平台总量（若有）、实际获取量、分页/分片、截断和去重方式。
- 文件交付前逐项检查上述门槛。篇幅不是目标，不得重复凑字数；结构、证据链和可复核性才是验收标准。
